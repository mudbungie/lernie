Filed from yog's tracker as bl-a942 ("`lernie scan` exits 1 for a root recipient
with pending mail"). **That framing is wrong and the repro disproves it** — the
real trigger is a different branch entirely.

## What actually happens

```
$ lernie new $W
$ git -C $W/repo.git branch agents/20260727T031141Z-2c8fbe03 <tip>
$ mkdir -p $W/inbox/20260727T031141Z-2c8fbe03
$ printf -- '---\nfrom: user\n---\nhello\n' > $W/inbox/.../user-001.md
$ lernie scan $W
silent deaths: 0; died deposits swept: 0; drivers launched: 1; inboxes with no agent branch: 0
$ echo $?
0
```

A **root with pending mail scans clean**. Now add the sibling branch the same
fixture laid — a one-token descent suffix:

```
$ git -C $W/repo.git branch agents/20260727T031141Z-2c8fbe03-c0ffee <tip>
$ lernie scan $W
lernie scan: git ls-tree messages: git ["ls-tree", "-r", "--name-only", "agents/20260727T031141Z", "--", "messages"] exited with exit status: 128: fatal: Not a valid object name agents/20260727T031141Z
$ echo $?
1
```

Exit 1, and **the whole pass is aborted** — the sweep dies before the flush, so
the mail that *was* going to be flushed never is. The mail is a bystander; the
failing branch need not have any.

## Root cause

`scan::sweep` (`src/prompt/inbox/scan/mod.rs`) derives the parent address with
`inbox::parent_of` — pure string arithmetic over the hyphenated descent (§2.3:
each segment is exactly two hyphen-free tokens, `<ts>-<short>`) — and then hands
that string straight to `derive::returned`, which runs `git ls-tree` on
`agents/<parent>` **without ever asking whether that ref exists**. Any
`agents/*` branch whose token count is odd, or whose parent branch was deleted,
yields an address with no ref, and git's 128 becomes `ScanError::Git` and a
non-zero exit for the operator.

`20260727T031141Z-2c8fbe03-c0ffee` is three tokens, so `parent_of` strips the
trailing two and returns `20260727T031141Z` — a ref that never existed. lernie
would never mint that id, but `lernie scan` is an operator verb over whatever
`agents/*` refs a workspace holds, and `name::require_agent_id` accepts any
single path component, so such a branch is reachable through the front door
(`lernie message`, `lernie dispatch`) and is exactly what an external frontend
laid here.

## The fix — the existing intersection, applied to the other half

This is not a new rule. ARCH §2.11 already governs the flush side: *"an inbox
directory whose name carries no ref names no agent, so there is nothing to
drive ... The pass counts it as debris an operator may delete and otherwise
leaves it in place."* And §8 scopes the sweep's second condition to *"or, for a
**child**, never deposited a result message"*.

The sweep never applied either. `parent_of` gives the **address**; whether that
address names an existing agent is a **query against the `agents/*` registry**
(§2.3: "the ref namespace *is* the registry, so existence is a query, never a
stored fact") — and `scan` has already enumerated that registry and passes it to
both halves. So:

    let parent = parent_of(&branch).filter(|p| agents.contains(p));

A branch whose derived parent holds no ref is, for the sweep, exactly a root:
no parent inbox to deposit into, nothing to ask git about. That dissolves the
class rather than special-casing the malformed id, and it is the same
intersection `flush` already performs — one seam, both halves.

## Exit semantics

**Unchanged, and correct as documented.** `scan::cli_run`'s contract is *"An
operator verb is loud, not best-effort: errors propagate to a non-zero exit
rather than being swallowed."* Mail presence is not and never was an error
signal (repro above: exit 0 with a driver launched). The defect was a *genuine*
error path reached on a non-error state. The fix removes the false error; it
does not soften the loud one.

## Deliverables

- The registry intersection in `scan::sweep`.
- Unit coverage: a branch whose derived parent has no `agents/*` ref is not
  swept, raises no error, and does not stop the flush that follows.
- ARCH §8: say that "for a child" is decided by the ref registry, the same
  intersection the flush states one section up.
