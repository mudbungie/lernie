Settled invariant (design discussion 2026-07-09/10): NOTHING context-bearing sits in memory. ARCH §2.3 currently claims both 'model conversations replay from in-memory message history while running' AND 'from commit + context assembler at replay time' — both arms fail: in-RAM history violates PRINCIPLES Disk-first ('processes hold none of it across restart'; crash/exec-baton recovery cannot rebuild history without reading response.json content, which §2.3 bans), and replay cannot be bit-for-bit because prior assistant text/thinking blocks have no readable home (tools/input.json+output.json cover tool framing only).

Deliverable: living amendment to docs/ARCHITECTURE.md (§2.3, §2.11, §5; PRINCIPLES as needed) establishing:
1. Every context-entering artifact is a committed worktree file — assistant step output included (and likely tool results, so rm/compaction curation covers them; git-history bloat handled by the existing compaction-squash contract §5.4). steps/ becomes purely diagnostic with zero runtime-content reads.
2. Sequenced, immutable transcript files: order lives in the filename sequence (NNN assigned at commit by the executor, single writer per §2.11 lock) — assembly is readdir+sort, NO git-log walk. Change is append or delete, never edit-in-place.
3. Append-only assembly between compactions (prompt-cache prefix stability): pinned head frozen at dispatch (goal/soul/descriptions), then sequence order — NOT manifest category order. Manifest category order applies only at rebuild points (dispatch, compaction). Compaction is the sole sanctioned reorganization/cache-flush point, and is a merge operation.

Open questions to resolve IN the doc (discussion ongoing): (a) self-output routed through inbox/ queue vs direct delivery commit — current lean: inbox is the async on-ramp for external senders, executor's own output delivery-commits directly into the same sequence namespace; (b) wire role framing (assistant-role blocks) derived by the assembler from file path/frontmatter (messages/NNN-assistant.md style) vs single assembled user block; (c) whether transcript-delete-at-terminal-compaction can replace the merge=ours + alignment-commit machinery of §2.6 entirely; (d) goal/soul as sequence item zero vs separate pinned files.
