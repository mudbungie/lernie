## Scope
§2.2 makes config-commit authoring a harness-assisted user act: 'lernie materializes a checkout, writes the files — from the <config-root>/workflows/ templates and the data-root pools, including the descriptions/** snapshot (§3.3) — and commits.' The workspace-substrate epic (bl-a51c) shipped this for the FIRST config commit only (inside `lernie new`). Still missing, the general act:

- Advancing an existing config branch (edit workflow/providers/souls/manifest → new config commit) without hand-rolled git worktree juggling.
- Creating additional config branches (fork from an existing config head, or a fresh orphan root) — 'config/strict-verifier' etc., §2.2.
- Refreshing the descriptions/** snapshot from the data-root pools as part of an authoring pass (§3.3 descriptions-always producer's ongoing home).
- Surface shape TBD against §3.4 (one CLI verb, e.g. `lernie config <workspace> [<name>]`): materialize checkout → hand to $EDITOR or take files → commit → teardown. Keep the §2.3 branch-advancement invariant: only this user act moves config branches.

## Context
Tests and users currently amend config/default by hand (git worktree add / edit / commit / remove — see workspace::fixture::amend_config and the integration tests' amend helpers). That is the workflow this verb absorbs.
