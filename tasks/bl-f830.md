cargo fmt --check fails on main with 62 diff hunks under current stable rustfmt (1.9.0 / Rust 1.95): the repo was formatted under an older toolchain and nothing pins one — no rust-toolchain.toml, CI uses dtolnay/rust-toolchain@stable (floating), and the pre-commit hook gates only coverage + the 300-line cap, so fmt/lint drift lands invisibly. clippy is clean as of bl-51ef. Fix: (1) cargo fmt the repo under a pinned toolchain; (2) add rust-toolchain.toml so hook, CI, and every agent format identically (same lockstep reasoning as the tarpaulin 0.35.2 pin in tarpaulin.toml); (3) consider folding fmt-check + clippy into .githooks/pre-commit so make check cannot drift from what the close gate enforces — the Makefile stays the single source of what the gate is. Note the toolchain choice interacts with brazen's rust-version 1.85 and edition 2024.
