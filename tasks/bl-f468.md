THE ACT. The operator has greenlit the coordinated cutover (yog REMOTE §12): the
seat's first release under this name, at 0.1.0. This is the moment the name
`lernie` publicly changes meaning — through 0.0.x it was the agent-loop engine,
which continues as `litany`; from 0.1.0 it is the seat. The version is the only
rule separating the two eras in the published record, and it cannot be corrected
in place, so the README that ships IS the disambiguation.

WHAT THIS BALL DOES.

1. Run the AGENTS.md *Before the first publish* checklist in full — all seven
   items — and record each verdict here. It is a person's checklist rather than
   a gate on purpose: every item is a one-time judgement whose remedy is
   destructive, so a green checkbox would be a worse answer than looking.
2. Audit the real `cargo package --list` against what the guard promises. The
   guard judges file CLASSES and never content; auditing the content of the
   list is the half only a person can do.
3. Flip `publish = false` to publishable, with the manifest comment rewritten
   to say what actually holds now. THE FENCE STATEMENT STAYS — the version rule
   outlives the flag, and it is the thing a later editor most needs to read.
4. `cargo publish --locked`, then verify the registry serves 0.1.0 and that its
   rendered page carries the fence-stating README.

WHAT THIS BALL IS NOT. It is not a release workflow. There is deliberately no
`make publish` and no automation for this act; a convenience target for an
irreversible act is how the act happens by accident. The recurring release path
is filed separately.
