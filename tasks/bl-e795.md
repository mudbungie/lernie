## Problem
The workspace seed (template/providers.yaml etc.) is embedded in the binary via include_dir. It hardcodes provider: anthropic / claude-sonnet-5. On a machine whose only credential is codex OAuth (this one: ~/.local/share/brazen/credentials/codex.json, no anthropic key), every 'lernie new' workspace is born pointing at an unusable provider and its first step dies with kind:auth. Proven live 2026-07-21: rewriting a workspace's config/default providers.yaml to provider codex / model gpt-5.4 (plus a models.yaml entry gpt-5.4: {provider: codex, capabilities: [tool_use_native, streaming], context_window: 400000}) produced a green end-to-end reply.

## Fix (severability: policy lives in config, not code)
'lernie new' resolves its seed set as: the union of embedded template files, with any same-named file under <config-root>/template/ overriding the embedded one (extra files in the override dir are included too). No new flags, no new verbs. Absence of the dir = today's behavior exactly. This mirrors the models.yaml pattern (install seeds-if-absent; user-edited config wins). 'lernie prime' does NOT seed template/ — absence is the default.

Note LERNIE_HOME collapse: with LERNIE_HOME set, config root == LERNIE_HOME, so the override lives at $LERNIE_HOME/template/. yog's nested world will use exactly that.
