**Status: BLOCKED / premature — cannot proceed until the subagent step loop exists. Left open and unclaimed deliberately.**

## What this task is
ARCH §6 "clamped inheritance": when a parent conversation dispatches a child, the child's *effective* budget = `clamp(remaining(parent), child_declared)` per axis — tokens/wall deplete by the parent's derived spend; `max_depth` is a shared absolute ceiling. The child then enforces that effective budget at *its own* model-call boundary. Commit d3730e3 (v0.7) shipped and unit-tested the three functions this needs, all in `src/prompt/budget/mod.rs`:
- `remaining(repo, parent_branch, parent: &Budgets) -> Budgets` (parent leftover, saturating)
- `clamp(parent_remaining, child_declared) -> Budgets` (per-axis `min`)
- `check(repo, child_branch, effective: &Budgets) -> Option<Exhausted>` (boundary check)

It left the hand-off unwired because there is no child model-call boundary to wire it into. This task is that deferral (commit d3730e3: "clamp/remaining are unit-tested + the dispatch-time hand-off wires when subagent loops ship").

## Why it cannot proceed yet
The clamped hand-off is consumed at a *subagent's* model-call boundary, and no subagent step loop exists. Evidence (verified 2026-07-08):
- The only model-call driver in the tree is `run_exchange` (`src/prompt/dispatch/mod.rs`), which drives *root* conversations off `main` and is the sole caller of `model_call::run`. It already wires `budget::check(repo, &branch_name, &resolved.budgets)` at its boundary (mod.rs line 128), but the root "has no parent to clamp against, so its declared budget is its effective budget" (mod.rs comment lines 126-127) — so `remaining`/`clamp` are never reached from it.
- `worker::run` (`src/prompt/worker.rs`, "v0.4 Phase 1") lands only the dispatch snapshot — branch + worktree + `goal.md`/`soul.md` + dispatch commit — then exits. Its module doc: "The subagent's own step loop, the `dispatch` and `await` tools … and the merge-back path — Phases 2/3/4 — slot in on top of this commit." No `ModelCall`, no loop. Called only from `src/bin/lernie.rs` (`lernie dispatch worker`).
- The `dispatch` built-in (`src/prompt/tool/builtin/dispatch/mod.rs`) spawns via `lernie dispatch <role>` and returns `{status:in_progress, handle}`; its module doc: "The subagent's own step loop and merge-back are Phases 3/4/5 — out of scope here."
- Grep confirms `budget::remaining` and `budget::clamp` have zero consumers anywhere outside their own unit tests (`src/prompt/budget/tests.rs`).

## Design tension the wiring must resolve first (ARCH §6 is underspecified here)
The clamp is NOT a pure derivation the child re-computes at each of its own boundaries. `derive::spend(repo, parent_branch)` sums over the parent's descent (`steps/<parent>-*/`, `src/prompt/budget/derive.rs`), which *includes the child's own spend* once the child starts. So re-deriving `remaining(parent)` at child-check time would double-count the child's spend. The budget module doc flags exactly this: "a hand-off that cannot be re-derived once the child starts spending (the parent's subtree spend then includes the child's)" (`src/prompt/budget/mod.rs` module doc, "Clamped inheritance"). The effective budget must therefore be captured at *dispatch* time (a snapshot handed to the child), and the child checks its OWN subtree spend — `check(repo, child_branch, &effective)` — against that frozen effective limit. Where that snapshot lives (a dispatch-commit artifact vs. passed into the child loop's `Resolved`-equivalent in memory) is a §6 decision to make when the loop is designed. §6 does not spell out the storage, and PRINCIPLES SSOT discourages a stored counter; this must be pinned as part of the step-loop design, NOT guessed under this ball.

## What must ship first
The subagent step loop (v0.4 Phase 2+): a driver analogous to `run_exchange` but for a child branch spawned off a *parent* (not `main`) — resolve config, drive `model_call::run` in a step loop, run tool calls, merge back (§2.6). That is major unfiled work; do not build it under this task.

## What the wiring will look like once the loop exists
At the child driver's model-call boundary, replace the root's `budget::check(repo, &branch, &resolved.budgets)` with:
```
let parent_remaining = budget::remaining(repo, parent_branch, &parent_budgets);
let effective = budget::clamp(&parent_remaining, &child_declared);
if let Some(ex) = budget::check(repo, child_branch, &effective) {
    budget::mark_exhausted(&child_worktree, child_branch, git)?; // writes refs/lernie/budget-exhausted/<child>
    // cease the child's step loop — ordinary terminal state (§6)
}
```
`parent_budgets` and `child_declared` are the same frozen `workflow.yaml` limits (one copy per conversation tree, §6), so in practice the clamp resolves to the parent's remaining headroom. This mirrors `run_exchange` mod.rs lines 128-138 exactly, differing only in (a) the clamped `effective` in place of `resolved.budgets`, and (b) the branch being the child's descent branch, not the root conv-id.

## Recommendation
File the subagent step loop as its own task and set this task to `--needs <that-id>`. Do not force an implementation here.
