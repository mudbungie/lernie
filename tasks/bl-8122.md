## Problem 1: stale process model in §3
ARCH §3.1 'Threads, not processes' ('worker and executor name roles that run as threads inside the single harness process') and §3.2's harness definition ('the single program that drives execution: watches for events…', 'permitted synonym: daemon') contradict the workspace-substrate model: transient per-agent drivers (§2.11 executor lock, deposit-starts-a-driver), the §6 exec baton, and 'no resident watcher (none is permitted)' (§2.11). §2.1's transition note already flags §3 as pre-ladder voice; this is more than re-voicing — it describes a resident event-watching process that the architecture forbids. Rewrite §3.1/§3.2 to the transient-driver model (and drop or invert the 'daemon' synonym) before `lernie advance` is implemented against the wrong model.

## Problem 2: network filesystems
The executor-lock singleton is kernel-local flock(2) (§2.11); on NFS and friends it is advisory-to-broken and nothing detects it — two executors on one branch, silently. Add one line (§2.11 or §1.1): a workspace on a network filesystem is an unsupported configuration.

Docs-only; no code.
