Foxglove finding 1, release-critical. Neither src/prompt/tool/builtin/bash/mod.rs:103 (Command::new(shell)) nor src/prompt/tool/subprocess.rs:123 ever calls .current_dir(). Verified live: agent's 'echo hello > out.txt' via the bash tool landed in the OPERATOR'S shell cwd (the lernie repo!), not <ws>/agents/<id>/. Consequences: an agent can never produce a work product on its own branch via bash (voiding the §2.6 work-product transfer story), and a detached 'lernie advance' driver's tools act on whatever cwd the launcher had. Fix: every tool subprocess (built-in bash, external tools, all of them) runs with cwd = the calling agent's worktree; check ARCH §3.3's env bullet for the specified contract and align the doc if it is silent. Tests: a bash tool write lands in the worktree and is committed by the tool commit (git add -A commit_tool already stages it — verify that now actually captures it).
