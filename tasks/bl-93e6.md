Diagnosed from a live yog run, 2026-08-02 (yog dev workspace agent
`20260802T223426Z-1277061f`, "energize"). Two prompt-side faults, one
deliverable: the `dispatch` skill text and the worker soul.

**Shipped 2026-08-03.** Prose only, no harness change — see *What shipped* and
*Judgement calls* below.

## 1. Agents burn paid steps polling for a dispatch result

After dispatching, energize spent **six consecutive steps** on shell sleeps:

    bash {"command":"sleep 2; echo waiting-for-subagent"}
    bash {"command":"sleep 3; echo checked"}
    bash {"command":"sleep 3; echo waiting-for-findings"}
    bash {"command":"sleep 5; echo checked-again"}
    bash {"command":"sleep 5; echo final-check"}
    bash {"command":"sleep 5; echo waiting-second-agent"}

(`messages/010`–`026`.) Six model calls, one per sleep, producing nothing.

The skill said the result "arrives on a later step as a message in your inbox"
— but never said that **ending the step is how you wait**, and the model had no
way to infer it: from inside the loop, stopping looks like giving up. The
deposit revives a quiescent agent (§2.11), so parking is free and polling is
pure burn.

## 2. A worker handed `dispatch` delegates instead of working

The operator asked energize to have a child agent analyse yog's XDG tree. What
happened (agent-id descent shows the depth):

    …-2962f775  →  …-1591b815  →  …-0c789cd1  →  …-1cf7d465

Four levels, each generation dispatching rather than looking. The level-1 child
ended its step — a `final-response` terminal, its whole contribution to the
goal — with:

> Spawned a subagent to inspect Yog's XDG paths and files safely. I'll report
> its findings when it finishes.

The parent had to message it back ("Do not merely say another subagent was
spawned"), and in the end did the work itself. Two gaps: the worker soul did
not say the goal is yours to *do* and delegation is the exception; and nothing
said that "I delegated" is not a legal terminal response to a goal, which is
what makes the regress self-sustaining.

## What shipped

Four prompt surfaces, all in this repo's shipped sources (`skills/` is embedded
by `include_dir!` in `src/install.rs`; `template/` by `src/template/mod.rs` —
neither is a generated copy):

- **`template/souls/worker.md`** — two new paragraphs. *The goal is yours to
  execute, not to route* (a child sees only the goal text and its branch's
  tree, never your reasoning, so each hand-off pays a fresh agent to rediscover
  what you know; reporting that you dispatched is not answering a goal). And
  *waiting is free; polling is not* — do not sleep, do not re-run a command to
  let time pass, do not poll; make other progress, and when you have none, stop
  emitting tool calls, because a deposit into a quiescent agent starts a driver
  (§2.11). The soul is `pinned` in `template/manifest.yaml`, so this text is in
  context at every model call — the right home for a rule whose violation
  happens many steps after the dispatch.
- **`skills/dispatch/SKILL.md`** — a new `## Waiting` section carrying the same
  rule at the point of temptation; a first `When not to use` bullet making the
  do-it-yourself default explicit; and the frontmatter `description` (snapshot
  into `descriptions/skills/dispatch.md`, also always in context) restated to
  lead with separability and to say the goal is yours. Re-voiced out of the
  retired vocabulary at the same time — "subagent"/"conversation" are gone
  (§2.1 ladder), and the `handle` output field is now named for what it is: the
  child's **address**, "not something to poll" (§2.5 — *never a handle to
  poll*). Two stale claims corrected: the result is not "compacted" (the result
  message carries the terminal response verbatim, §2.6), and the child's
  worktree is `<workspace>/agents/<child-agent-id>/`, not `<conv-repo>/<handle>/`
  (§2.2).
- **`skills/message/SKILL.md`** — one Notes bullet: a reply is a deposit like
  any other and you wait for it by ending your step.
- **`skills/bash/SKILL.md`** — one `When not to use` bullet: `sleep` is never
  how you wait for another agent, with the local-process case explicitly
  carved out as still fine.

`CHANGELOG.md` carries the `[bl-93e6]` bullet under `[Unreleased]`.

## Judgement calls

**No harness change; prose only.** The depth signal the ball asked about
*already exists and is already enforced*: `budgets.max_depth` is checked at the
fork, in the one place a tree can deepen (`src/prompt/child_dispatch.rs::run` —
"the check belongs at the fork, not at the child's first model call, and there
is exactly one fork in the system"), and `template/workflow.yaml` ships
`max_depth: 4`. The observed regress reached exactly depth 4 and stopped there;
the operator's stop was a judgement about waste, not a breach of a missing cap.
So the harness lacked nothing — the *reason* to not delegate is what was
missing, and a reason is prose. A fan-out cap would have been a genuinely new
knob (global AGENTS.md: "New flags/config/verbs are a smell"), and it would
punish the legitimate shape the skill recommends — N dispatches in one step for
parallel exploration. Declined. Note also that the structural half of this
runaway was already fixed by bl-5a36 (the child dialog prune): what remains is
the model's own judgement, which is a prompt surface by definition.

**The `message` skill did need it.** Its existing line — "There is nothing to
poll and no address to capture — the message either drains at the recipient's
next boundary or wakes a quiescent recipient" — is about *the deposit's own
fate*, i.e. the sender needs no delivery receipt. It says nothing about what to
do while awaiting a *reply*, which is the same burn one primitive over (and
energize's parent did exactly this: message the child, then wait). One bullet,
pointing at the same rule, rather than a second copy of the paragraph.

**`bash` was added beyond the ball's brief**, because it is where the wrong act
is actually taken: an agent reaching for `sleep 5` reads the `bash` skill's
*When not to use*, not the dispatch skill. One bullet, with the legitimate use
(letting a locally backgrounded process settle) preserved so the rule is not
over-broad.

**The honest cost of parking is stated, not hidden.** A step that emits no
`tool_use` *is* the terminal event (`src/prompt/dispatch/advance/hop.rs`:
"No `tool_use` block is terminal (§2.5): deposit a `final-response` result"), so
for a non-root agent parking and reporting are the same act. Telling a worker
to "just end your step" without that would have manufactured fault 2 out of the
fix for fault 1. The text therefore says: park on an outstanding child only when
what you have to say is worth returning — and if all that was left to do was
wait, you did not need the child. That single sentence ties the two faults into
one rule.

**Deliberately left out.** The `handle` key on the dispatch tool's wire output
(`{"status":"in_progress","handle":…}`) still contradicts §2.5's "never a handle
to poll". Renaming it is a code + test change with its own compatibility
question and belongs in its own ball; the skill now defuses it in prose instead.
The pre-ladder "conversation" wording surviving in `skills/bash/SKILL.md` was
also left alone as out of scope.
