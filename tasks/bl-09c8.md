Evidence (run 33611717922, the merge of release PR 7, and expected on every push since the snapshot harness landed): two tests fail on the CI runner and pass locally — snapshot::tests::a_label_that_reached_the_glass_is_quiet_and_one_painted_over_is_not and snapshot::tests::the_matrix_renders_every_world_at_every_size_and_the_frame_holds — 429 others pass. The release job is gated on that CI job and was skipped, so the crate cannot ship until this is green. Newest published lernie is 0.1.5; 0.1.6 was version-bumped on main but never released.

Diagnosis to verify, not assume: the runner has no GPU and no vulkan ICD, so wgpu finds no adapter for kittest rasterization. The house-standard fix is a software vulkan: install mesa lavapipe on the runner (mesa-vulkan-drivers + libvulkan1 via apt) in the CI job before the gate step — this is how egui upstream CI runs kittest. Prefer making the runner able to render over skipping or gating the tests: the snapshot invariants are load-bearing and a cfg-off in CI would silently unfence them. If lavapipe genuinely cannot work, the fallback is an explicit software-adapter selection env for wgpu, stated in the workflow with its reason.

Constraints: keep the CI gate otherwise identical (make ci). Prove the fix by pushing a PROBE branch with a PR to buy a runner verdict (the sanctioned probe use), read the verdict, land through bl close, then DELETE the probe branch and close its PR in the same breath. Once green, confirm the next main push runs green end to end including the release-plz jobs.
