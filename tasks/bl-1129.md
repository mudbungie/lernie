ARCHITECTURE §2.11 Delivery: at each step boundary — after the prior step's tool entries commit, before the next model call's context assembles — the executor drains its inbox: each pending file renames into the worktree as messages/NNN-<sender>.md (NNN from the branch's single transcript counter, inside the lock) and is committed (the delivery commit). The move is a literal rename — the message file has exactly one home at every instant — and a drain begins by committing any renamed-but-uncommitted stray a prior crash left in messages/. Out of scope: the result message's work-product transfer (bl-4ce8 — this ball moves files, that one applies diffs).
