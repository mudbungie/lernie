PASS. Checked bl-7318's delivery (main 6a4a47d) against ARCHITECTURE.md, PRINCIPLES.md, TAXONOMY.md.

**ARCHITECTURE 2.11, *The executor lock*.** The invariant is 'at most one executor per branch', mechanised as `flock(2)` on the inbox-directory fd, 'kernel state bound to process lifetime... observable but never written... no stale-lock cleanup because there is nothing on disk to go stale'. The fix keeps every clause: same primitive, same home, nothing written on release, still kernel-released on death. What it changes is that a *voluntary* release is now exact rather than emergent — and the doc was amended to say so rather than left to imply the old behaviour (see bl-e3b6). Deviation-free by construction: this is the doc-fix path the repo's guidance names, not an undocumented divergence.

**ARCHITECTURE 2.11, Writer/driver totality.** 'A driver acquires-or-exits: winning the acquire, it *is* the executor...; losing it, it has nothing to deposit and exits as a clean no-op — not an error, because the branch being already driven is the condition it exists to establish.' The bug made that condition *falsely* true: a half-forked child about to `exec` into `git` is not an executor, yet the probe reported one. The fix restores the predicate's meaning; it does not add a code path, a flag, or a tolerance. The losing arm is still the same code as the uncontended one.

**ARCHITECTURE section 6, exec baton.** Untouched behaviourally: `successor_command` `mem::forget`s the guard immediately before exec, so the new `Drop` never runs on the handoff path and the documented 'no release-reacquire gap' still holds. The section's one false sentence about close-on-exec was corrected, not worked around.

**ARCHITECTURE section 8, silent-death sweep.** 'An agent branch with no live executor (the 2.11 lock probe)...' — the sweep's whole classification rides this probe, which is why a spurious hold read a dead child as live. Same fix, same seam, no sweep-side change needed.

**PRINCIPLES.** *Single source of truth*: the lease stays kernel state with exactly one home (`src/prompt/inbox/lock.rs`, the tree's only `libc::flock` call site); nothing new is stored or mirrored, and release remains 'no stale-lock cleanup'. *Structure over discipline*: the guarantee moved into the type — `ExecutorLock`'s `Drop` is the only way a lease is given up, so no call site has to remember. *One obvious path*: no new verb, flag, config, or default; the diff is one `Drop` impl. *Decline illegal operations* is unaffected — the adopt path still refuses a bad fd loudly rather than reacquiring. *If it can't be tested, it mustn't be built*: the new behaviour has a deterministic unit proof with no wall-clock verdict, and the rejected fcntl alternative was rejected precisely because it would have destroyed the in-process contention the suite uses to stand in for a rival executor — testability weighed as a first-class constraint.

**TAXONOMY.** No new term of art introduced. 'lease' and 'executor lock' are pre-existing (ARCH 2.11, `lock.rs`); 'open file description', 'close-on-exec', `LOCK_UN` are POSIX vocabulary, not lernie coinages. No banned term used (no bare 'call', 'turn', 'session', or 'compression').

**Subtraction check.** The delivery adds 41 lines to `lock.rs` (35 of them the doc block explaining the failure mode), 38 test lines, and 2 doc sentences. It removes no capability and introduces no mechanism: no retry, no timeout, no registry, no lock file, no new global. The alternative designs that *would* have added mechanism (a spawn mutex; an fcntl lease file plus an in-process registry) were attacked and dropped in favour of the one-syscall correction. Coherent.
