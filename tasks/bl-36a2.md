Operator decision 2026-08-01 (recorded in yog bl-3381): *"lernie becomes the clock."* The fleet design (~/ops/fleet) currently drives watcher cycles from cron — its GAPS list names this first: *"No harness clock. lernie has no watcher and no scheduler by design (ARCH §8: an idle workspace stays unswept until the next touch). … A fleet whose cron is not installed is a fleet whose watchers never wake, and nothing in the harness notices."*

This ball is the design + implementation of the clock in lernie. ARCH §8's 'no scheduler by design' is amended by this decision — fix the doc as part of the work, don't design around it.

## What exists

A cycle today is just a message deposit: `fleet-cycle.sh` runs `lernie dispatch`/deposit on a cron cadence. lernie has no long-running process; every verb is a short exec over the workspace substrate.

## Design questions (open — the deliverable is a design section in ARCH or a tracked doc, then the implementation)

1. **Process model.** A long-running `lernie clock <workspace>` (or fleet-wide) process owning timers and depositing cycle messages? Or scheduling data in the governing config commit that any driver honors? The severability test applies: cadence policy belongs in config (the capability), not hardcoded in the core.
2. **Where cadence lives.** Per-role cadences (shepherd 1m, sensor 2m in the demo) should ride the workspace's governing config commit like every other control fact (ARCH §2.2), so a config edit changes the clock without touching a crontab.
3. **Cost discipline.** The fleet README: *"Each watcher cycle costs at least one model call, and revives the coordinator"* — ≥2 model calls per cycle minimum. The clock design should make idle cycles cheap or skippable (e.g. deposit only when a condition holds, or an idle-detection cheaper than a model call) rather than merely reproducing cron's unconditional fire.
4. **Liveness visibility.** The cron gap's sting was silence ("nothing in the harness notices"). The clock must expose 'when did this watcher last wake / next wake' as derivable state so an operator surface (yog) can render it.
