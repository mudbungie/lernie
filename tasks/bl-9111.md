## The contract this seat consumes

PROTOCOL is **17**. Four shapes already decoded here gained a field, each in the one figure shape `reply/spend` already reads (`{"micro_usd", "usd", "unpriced_tokens"}`, the key ABSENT when the engine has no price table):

- `reply/steps` rows: `cost` — that step's own bill, priced.
- `reply/science` attempts: `cost` beside `usage`.
- `reply/rail` notches: `cost` beside `budget`.
- `reply/workspaces` rows: `spend` — the workspace's whole priced figure. This is the per-workspace ledger this ball's predecessor asked for.

One new read and two new acts, window-level (they address no wall — the table and the bound are world facts, yog DESIGN §4.1; place them with `workspaces`/`clients`, lernie DESIGN §4.21):

- `Query::Prices` → `{"kind":"prices","rows":[{"provider","model","input","output","cache_read","cache_write"}],"ceiling":<usd>,"spent":<cost>}` — `ceiling` and `spent` absent when unset/unpriced; a `"*"` model is the literal string and means "every model this row serves that it does not name"; `{}` rates is a row priced at zero (a subscription — paints `$0.00`, never blank).
- `Action::Price { provider, model, rates? }` — slash `/price <provider> <model> <input> <output> [<cache_read> [<cache_write>]]`, `/price <provider> <model> off` deletes. Receipt: the re-derived `prices` reply.
- `Action::Ceiling { usd? }` — `/ceiling <usd>`, `/ceiling off`. Receipt: the same reply plus `"released": <n>` (conversations the ceiling had parked and the act woke).

## What this seat does

1. **Decode** the four gained fields (`src/reply/steps.rs`, `reply/science.rs`, `reply/rail.rs`, the workspaces row) through `reply::spend`'s existing figure/cost reader — one reader, never a second multiplication (`reply/spend.rs`'s own header: "the money is upstream's own rendering, and this seat does not compute one"). Decode `reply/prices`.
2. **Paint the cost beside every token count.** Today `render/records.rs` says `N tokens` on a step row, a rail notch and a candidate card; `render/chat.rs` says `spend N`; `render/tasks.rs` already appends `$`. The rule (yog DESIGN §3.5): a token count is never painted without the cost the engine put beside it — `N tokens — $x.yz` where present, `N tokens` alone where absent, and `at least $x.yz` when `unpriced_tokens` is above zero. Same on the window: the records pane's step rows (§4.18), the spine's notch (§4.29), the candidates screen (§4.36), the workspace list (the ledger column: each wall's `spend`).
3. **The verbs**: `lernie prices`, `lernie price <provider> <model> …|off`, `lernie ceiling <usd>|off` as rows in `crate::verbs` (window-level, like `workspaces`), with the summary/reasoning text the verb table carries. Validate the provider name against the wall's `providers` roster where a wall is aimed, and let the engine's in-band refusal name it otherwise.
4. **A prices surface on the window**: one pane on the window-level reads' standing (§4.21), showing the table, the ceiling, the world's spend against it, and the two acts as controls — parity-tagged (`act:prices act:price act:ceiling`).
5. Stamp PROTOCOL 17; regenerate the corpus; lernie DESIGN amended (§4.18/§4.29/§4.36 gain the cost clause; a new §4.38 for the prices pane and the ledger column); the parity ledger updated.
6. Tests: every decode both directions with the field present and absent; a paint test per surface proving the `$` clause appears when `usd` is present and not when absent; the `at least` clause when unpriced tokens are non-zero.
