== WHAT WAS ACTUALLY BROKEN (and fixed) ==
The retry loop in src/prompt/dispatch/model_call.rs never consulted the stop flag. A stop landing during a backoff pause (or during an attempt that had already emitted a retryable in-band Error) let the loop spawn a FRESH `bz` — a process created AFTER the group SIGTERM, so outside the cascade's reach — burning a whole further model call before the caller's check point could settle the branch. That is the "stop button appears dead" symptom the ball describes.

== DESIGN (settle-as-stopped) ==
Rule: THE FLAG CLASSIFIES, THE ERROR'S SHAPE DOES NOT.
Deliberately did NOT narrow the check point to `AdapterHalfStream` (the ball's literal suggestion) — that would REGRESS. A mid-write kill tears a JSON line, which surfaces as Error::AdapterJson, not AdapterHalfStream; a kill after a failed attempt surfaces as AdapterError. None is distinguishable from a genuine fault by shape. So with a stop pending the caller discards WHATEVER came back; with no stop pending every one of them still propagates non-zero (exit 1). The broad swallow is the correct, total rule; it was just undocumented.

== SIGNAL/RACE HANDLING ==
- Stop DURING an attempt: `kill(-pgid)` reaches executor + bz together; handler sets the flag before the read returns (SA_RESTART), so the flag is already set when the attempt's error surfaces. Retry decision reads it -> no further attempt.
- Stop DURING the backoff sleep: `std::thread::sleep` restarts over EINTR, so the sleep is NOT shortened and the flag is the only evidence. Hence the flag is read on BOTH sides of the sleep.
- No check before the FIRST attempt: both callers already check at their step boundary immediately before.
