Requirement from yog (the desktop manager): yog is moving to a nested-world model where it runs lernie with LERNIE_HOME pointed at a yog-owned directory. A fresh home has no models.yaml, no skills pool, no tools pool — today only `make install` lays those down (models.yaml seeded if absent; skills installed into the data root). yog must be able to seed a fresh home by invoking lernie itself; maintaining a separate seeding implementation that apes lernie in a different codebase is explicitly rejected.

The verb: an idempotent bootstrap (name per lernie's own taxonomy — init/prime/found; balls' `bl prime` is the philosophical sibling: "founds the substrate on first run and converges after; nothing else readies the checkout"). Semantics: resolve the roots exactly as every other verb does (XDG split, LERNIE_HOME collapse); lay down whatever `make install` currently seeds — the default models.yaml, the skills pool, the tools pool/descriptions — creating what is absent and NEVER clobbering what exists (models.yaml is hand-edited by contract; seed-if-absent only). Print nothing surprising on stdout (follow the one-product convention). `make install` should then invoke the verb instead of duplicating the seeding logic (single source of truth for what a ready installation looks like).

Process expectations: follow this repo's own conventions (read AGENTS.md/CLAUDE.md); if the repo's process requires an ARCHITECTURE.md amendment for a new CLI verb, that amendment is part of this ball. Deliverable includes tests to the repo's own gate standards.
