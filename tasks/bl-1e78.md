Root cause of the three ~28s release-plz failures post-bl-53e3 (runs 30230749097 / 30231020727 / 30231178198): crates.io trusted publishing rejects the workflow_run event trigger outright ('Trusted Publishing does not support the workflow_run event trigger... use push, release, or workflow_dispatch'), then falls through to 'no token found... CARGO_REGISTRY_TOKEN'. The green-CI-gated auto-release design (workflow_run on CI success) can therefore never publish via OIDC. The workflow ALREADY carries the escape hatch: the release job's if: accepts workflow_dispatch, documented as 'Leave empty for a normal publish' — so  on a green main is the designed, no-code-change path to ship 0.0.1. Longer-term decision for this ball: either (a) accept workflow_dispatch as the permanent publish trigger and update the workflow header/docs to say the auto-fire on CI-green is aspirational-until-crates.io-supports-it, or (b) restructure the gating so the publish job runs on push with an internal green-CI check (e.g. gh api check-runs query) instead of the workflow_run event. (a) is the subtraction answer; (b) restores hands-off. Evidence in the named run logs. Note bl-53e3's config fix IS working — the agent-eval publish-consistency error is gone from these logs.
