**Needs an operator ruling before anyone claims it.**

The compactor may delete the dispatch message — the entry that records what the
branch was asked to do. `src/prompt/compactor/tools.rs` `mark_for_deletion` runs
`git rm` over any path the compactor model names, and its own test fixture is
`messages/001-user.md`. The shipped `template/workflow.yaml` sets
`every_n_commits, n: 20` with no `keep_recent`, so the compaction point is the
branch tip and entry 001 sits inside the squashed span by default. The soul's
only constraint is "Scope deletions to files within the dispatching branch's
diff", which does not exclude it.

ARCHITECTURE already treats the loss as expected rather than as a defect:

> A branch whose whole record of being prompted was squashed by compaction
> (below) falls back to the id: the dispatch message is the transcript's first
> entry, so its absence means the record was rewritten, and the id still
> carries the one sender the branch's own existence records.

Sighted downstream 2026-08-16: an operator lost the opening question of a live
conversation while the reply answering it stayed on screen. yog bl-7bd2 makes
that loss *visible* — it derives the gap and paints the summary that replaced
the span — but visible is not the same as prevented, and the question itself is
still gone.

**The ruling wanted:** is the dispatch message exempt from compaction?

The case for exempting it: it is the only entry that is not derivable from
anything else on the branch. Every later message is the agent's own work, which
the summary genuinely summarizes; the originating ask is an input, and a summary
of it is a paraphrase of the one thing nobody else recorded. It is also
bounded — exactly one entry per branch, so exempting it cannot grow the context
without limit, which is the pressure compaction exists to relieve.

The case against: it is a special case, and the house rule is that a special
case is usually a missing reframe. The general form might be `keep_recent`'s
mirror — a `keep_first` — or better, the observation that the compaction SPAN
should start after the dispatch rather than at the branch base, which is one
change to where the span is cut and no exemption at all. Prefer that framing if
it holds.

Do not implement either until the ruling lands.
