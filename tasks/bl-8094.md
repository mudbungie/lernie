## Scope
The platform's stated purpose — "Experiments are config diffs, measurable against a task suite" (§1 Testability) — is unmeasurable today.

## What "eval" strictly means here (2026-07-13)
The term is NOT defined in docs/TAXONOMY.md (only "evaluation harness" appears, as a harness variant) — defining it is part of this epic's docs gate. The sense used throughout is the spec's own operational one (§9.1/§9.3): an **evaluation run** is (experiment × suite × N) — run one workflow-config variant against the fixed task suite N times, machine-check each task's success criterion, aggregate pass@1 (mean-of-means, Wilson 95% CI) and pass@5. It evaluates HARNESS CONFIGURATION, holding tasks and models fixed. It is not: model capability benchmarking (MMLU-style), per-response LLM-as-judge grading (a task checker is a machine-checkable script), or online/production monitoring (§8's metrics own that).

## Deliverables, in order
1. Bundle/replay (§9.2): git bundle of an agent subtree + steps/ and inbox/ slices; replay = clone into a scratch workspace under LERNIE_HOME, restore slices, inspect with the ordinary frontend. Mostly plumbing plus a verb.
2. Task suite (v0.9): 50 tasks, machine-checkable, ≥10 per failure category, per-category tagging.
3. Runner (v0.10): agent-eval --config <experiment> --suite <suite> --runs N → per-task pass@1/pass@5 with CIs.
