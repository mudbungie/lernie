A workspace's providers listing carries, after the server's own rows, one row per provider per registered machine that offers its model access, named row@client (yog REMOTE 5.7). The seat painted that as one flat provider list, so an operator read a dozen rows where each machine has about four.

Ruling: seat, then servers and workspaces, then machines (the server itself and each registered machine offering its brazen), then providers, then models - each level its own menu. So a machine selector stands between the workspace and the provider. Its choices are the server plus each client that appears as a qualification in the listing; the provider list shows only the chosen machine's rows, without the qualification; the model list is unchanged.

Seat-only: the name the role assignment writes stays the qualified one. The machine is derived from the role's provider name and from the listing; the one new piece of state is which machine an open provider list is browsing, held in the dropup's open state. The providers reply carries no client field and the seat does not hold the registered set at the time it paints, so the reading is the last joiner in the name; DESIGN states where that differs from the server's own longest-registered-name rule. DESIGN 4.44 is amended in the same ball.
