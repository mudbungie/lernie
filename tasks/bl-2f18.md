yog bl-fec6 (REMOTE §8.4, PROTOCOL 14) put an optional `address` on `request/enroll`: the endpoint the DEVICE being enrolled will dial, which need not be the one the engine wrote for itself. The engine's own `/enroll` help now reads `/enroll <common-name> [foot] [--at <host>:<port>]` and says why — an emulator reaches its host through the emulator's alias, a phone by LAN address, a box by overlay name — so an envelope carrying the engine's own loopback view enrols a device pointing somewhere it cannot dial.

`lernie enroll <workspace> <name> <grade> [--into <dir>]` composes the three-parameter form only. bl-183b vendored the corpus at PROTOCOL 16 and recorded the frame in `src/verbs/tests/corpus/emits/ledger.rs` as one this seat cannot compose, which is the decision being written down rather than passed over.

WHAT IT NEEDS: the flag is not a boolean, so the `Verb` table cannot carry it — `enroll` already has its own `cli::Decided` arm for `--into` and this is a second value on the same arm, composed through a typed door (`src/verbs/doors.rs`) the way the tuning pair are. `--at` is the engine's own spelling and the seat should not invent a second one.

Also: state one the server leaf already answers to (`WIRE_HOST` is a list), because a route the certificate omits fails verification at the device rather than at the engine — that is a sentence `lernie help enroll` should carry, since the seat is where the operator types it.
