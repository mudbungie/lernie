Operator 2026-10-31: 'Change the icon for the desktop app to match the icon for the mobile app.'

Today src/mark.rs draws a ring, a disc and a wire, and its doc argues the seat must not share a picture with another program. That doctrine is overridden by this ruling: the desktop seat and the phone seat are two faces of one product and wear one mark. Amend the mark.rs module doc and DESIGN where the mark is described (search 'ring' / 'bl-8f48' / 'mark' in docs/DESIGN.md).

The source of the picture is yog-android's src/icon.rs + src/icon/arc.rs (the congeries as a circuit: three tangent circles 120° apart, 60° arms to further circles, casing + conductor traces, a lune pupil in VOID_DEEP; hues HYDRA [110,222,148] driven to phosphor/casing by deep()). Its drawable.rs emits Android vector XML from the same Shape list (Trace / Lune / Disc) and pins it byte-for-byte. Port the walk (icon.rs, arc.rs) into lernie as the new mark: same constants, same shape list, so the two seats' marks are one geometry. Emit (1) assets/lernie.svg — scalable hicolor icon, pinned byte-for-byte by mark::tests::artifacts as today — the mark over a background in VOID_DEEP shaped like the phone's launcher mask (a circle), so the two icons read alike on a desk and a home screen; (2) the toolkit raster rgba(size) for X11, from the same list.

Constraints that bit the original: the house lints deny numeric 'as' casts and there is no per-item suppression home. The phone's walk is f32; keep it f32 and avoid casts by construction — f32::from(u16) for pixel coordinates, u8::try_from / usize::try_from for counts, format!() for SVG numbers, and a coverage count per pixel that is an integer. The pinned SVG must be reproducible across targets: format floats with a fixed precision (the phone's drawable does '{:.3}'). No image or vector dependency may be linked (Cargo.toml's approved set). The leak gate's binary allowlist stays empty.

Tests: artifacts pinning, the rgba's size and that its centre pixel is the void and a node pixel is the hue, and the icon-seats agreement (APP_ID, desktop entry, SVG basename) unchanged. make icon-seats must still lay the installed SVG down. Then run make icon-seats on this laptop so the operator's desktop entry picks up the new mark (the installed file is a derivation, not tracked).
