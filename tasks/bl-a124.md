Found by Parrel landing bl-f021: crates.io HTTP 400 — "Trusted Publishing does not support the workflow_run event trigger due to security concerns" — so the workflow_run-gated release job could never publish, and the CARGO_REGISTRY_TOKEN fallback is deliberately absent (bl-6cfb chose OIDC).

DELIVERED (Quoin): the decided mechanism, exactly. ci.yml gained `workflow_call:` and LOST its push arm; release-plz.yml gained a `ci` job (`uses: ./.github/workflows/ci.yml`) and its release job now gates via `needs: ci`; the workflow_run trigger arm is retired. A called workflow executes inside the CALLER's run, so the OIDC claim carries trigger=push / workflow=release-plz.yml — the identity the crates.io trusted publisher binds (owner mudbungie, repo lernie, filename release-plz.yml, environment empty; neither file renamed).

Trigger topology after the change:
- push to main -> ONE run (Release-plz): ci (called CI, runs once per push — dedup by dropping ci.yml's push arm, not by concurrency hacks), release-plz-pr (push only), prune-release-branches (needs pr job), release-plz-release (needs ci), release-binaries (needs release).
- pull_request -> ci.yml directly, unchanged.
- workflow_dispatch -> same ci -> release -> binaries chain by hand (escape hatch, still CI-gated); binaries_tag backfill also rides behind the gate.
README badge repointed to release-plz.yml?branch=main (ci.yml has no runs of its own on main anymore). Header comments in both files rewritten to describe the real wiring, filename-immutability warning kept. `id-token: write`, owner guards, version/tag/Release/binary-attach behavior unchanged; no crates-io-auth-action added.
