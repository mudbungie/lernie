In PR #2's generated 0.0.2 changelog the bl-2bf0 entry rendered as '- :advance_cli baton test outruns…' — release-plz parsed the commit subject's leading 'e2e:' (from 'e2e::advance_cli') as a Conventional-Commit type prefix and stripped it, even though this repo's subjects are non-conventional (short imperative + [bl-xxxx], per release-plz.toml's own header comment). One-word cosmetic loss, already shipped in 0.0.2's CHANGELOG entry (hand-fix it when touching the file). Fix candidates: a commit_preprocessor in release-plz.toml that restores/protects 'word::' subjects, or accept and document that subjects must not start with 'token:' / 'token::'. Filed by Flophouses during the 0.0.2 promotion.
