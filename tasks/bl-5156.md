Foxglove finding 4. README/ARCH: the executor catches SIGTERM, deposits its stopped result on the way out, and exits CLEANLY — 'the observable is the clean exit'. Shipped: the stop flag is consulted only at loop boundaries (src/prompt/dispatch/stop_signal.rs); a mid-stream kill surfaces as HalfStream → hard error → exit 1 with 'adapter stream ended without a terminal end (killed mid-stream, §2.9)'. Since wall time is dominated by the model call, the documented case is the rare one — and the frontend stop button execs exactly this path. Fix: when the SIGTERM/stop signal is set, a HalfStream from the dying bz is the EXPECTED stopped signature (§2.9), not an error: settle as stopped, deposit the stopped result, exit 0. Without the stop signal a HalfStream stays an error. Align ARCH §2.9 wording if any nuance shifts. Tests: stop mid-stream → exit 0 + stopped epitaph; spontaneous HalfStream without stop → still error.
