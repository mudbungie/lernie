bl-8ee7 shipped the multi-tool serial: inner invocations run strictly in list order (src/prompt/dispatch/tool_step/multi.rs), documented in ARCH §3.3 *The multi-tool*. Codex's read/write split (codex-rs/core/src/tools/parallel.rs: read-safe tools share a read lock, mutating tools take a write lock) is compatible with the shipped envelope and deferred: adopting it costs a per-tool read/write classification — a new fact with no current home (schema? grant? tool triple?) — and buys wall-clock time only, which no defect has yet charged. If adopted: read_file/load_skill/message may share the window; bash/cd/dispatch/apply_patch (bl-ae6b, landed) take exclusive slots; commit-per-side-effect (§3.3) still serializes the commits, and an inner cd moving the shared cwd mid-window must be reasoned about. Do not build until a real workload shows the serial rung too slow. Note: block-on-all result delivery is NOT deferred work — it is a wire fact (one tool_result per tool_use id on every protocol brazen encodes) and stays.
