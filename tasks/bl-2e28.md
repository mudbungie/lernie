Deferred from bl-8801 (packaging hygiene). The evaluation runner `crates/agent-eval` (ARCH §9.3) is complete and fully covered, but its agent seam dangles at BOTH ends.

END 1 — no driver exists. `--agent <cmd>` names an external harness-driver program and NO SUCH PROGRAM SHIPS. Until one is written, no evaluation run (experiment × suite × N) can be performed and the §9.1 suite data (50 tasks) has never been measured against a live model — so the v0.10 success criterion is not met (ARCH §9.3 "Not yet runnable end to end", §11 v0.10 shipped shape).

END 2 — `LERNIE_EXPERIMENT` is read by nothing. `CommandAgent` sets it per run, but no code under `src/` reads that variable: the harness resolves `workflow.yaml` from the workspace config commit (§2.2), never from the environment. So the variable is a hand-off, and APPLYING an experiment — authoring the named workflow.yaml into the workspace config commit before prompting — is work the driver must do. Consequence: no experiment has ever reached the harness through this path, and §9.3's "a new experiment is a config diff; no code changes" is unexercised end to end. Writing the driver is what closes both ends together.

bl-8801 removed the phantom `lernie-eval-agent` default rather than leaving a spawn failure per task: `--agent` is now required, `make eval` requires AGENT=, a spawn failure names the program, and the driver contract (both ends) is documented in README "Run the suite".

The contract a driver must honour, per run:
- prompt: argv[1]
- LERNIE_HOME (env): the isolated harness root for this run
- LERNIE_EXPERIMENT (env): path to the experiment workflow.yaml — the driver must APPLY it (see END 2); nothing else will
- LERNIE_EVAL_REPORT (env): path of a file the driver MAY write with exactly two lines — workspace path, then agent id — which is what `lernie bundle` needs to archive a failing run (§9.2). Absent or malformed only makes the run un-bundleable; never an error.
- cwd: the working directory shared with the task setup and check
- the driver exit code is IGNORED; pass/fail is the task check alone (exit 0 the sole pass signal, §9.1)

Shape of the work: `lernie new` a workspace, author the experiment workflow.yaml into its config commit, `lernie prompt` the task prompt, then report the workspace path and root agent id. Decide first whether it is a binary in this repo (a second [[bin]] or a third workspace crate, publish=false) or a script under scripts/ — an integration is an external binary (docs/PRINCIPLES.md), so it must not become a lernie verb. Done when `make eval CONFIG=baseline SUITE=tests/suite RUNS=5 AGENT=<it>` produces a real pass@1/pass@5 report with the experiment demonstrably in force, and the honesty caveats bl-8801 added (ARCH §9.3, §11 v0.10, README "Run the suite", crates/agent-eval/src/agent.rs, tests/suite.rs, tests/suite/README.md) are retired in the same change.
