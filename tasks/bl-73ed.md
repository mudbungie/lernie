Upstream's rule is *a start focuses what it started* (yog's `docs/DESIGN.md` §3.4). This seat paints the minted name and does not select it, and DESIGN §6.6 records why: the name is a barrier only once the detached driver has written the conversation's branch, so a seat that selected it at once would publish three standing questions against an address the engine refuses — and paint the operator's own new conversation as unknown for the whole of a healthy start.

Upstream's answer is a held claim plus a synthetic row: the claim names the conversation by its minted name, carries the operator's goal so the text has a representation between Enter and the driver's first write, is spent when a roster carries a root under that name, and is spent *where it was made* — it moves the selection only while the selection is still the name the claim put there, so an operator who read something else in that minute is not yarded back.

What it costs here:

- The claim itself, beside the start the model already holds — the same value, not a second pending concept.
- A synthetic conversation row the list paints while nothing observed it: no lock, no completed step, flagged uncertain, which is what the engine's own classifier answers for a conversation it cannot probe. It must not read `live`.
- The predicate that spends it, and the rule that nothing is asked about a conversation the engine cannot resolve — the standing set must not publish a transcript question against a name that resolves nowhere.

Ordering: the standing-set half is the load-bearing one. A claim that paints a row while the asker keeps refusing against it is worse than no claim at all.
