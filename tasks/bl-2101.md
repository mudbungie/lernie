Operator 2026-10-31: 'The tool usage is currently all-collapsed, which isn't what I want. I want it to end up getting collapsed, but it should be expanded as it comes in, progressively collapsing. You send a message, get an intermediate response, which should be printed directly, then some tool calls, which are shown entirely until they are done, at which point they collapse, and only once we get back to the final response, everything should collapse.'

DESIGN §4.45 item 5 already rules this (2026-10-14: verbose while it happens, compact when done, one line once the answer stands) and chat/working.rs implements the three stages. The defect is upstream of it, in what 'running' means.

Cause (src/ui/chat/rows.rs rows() + rows/role.rs settle()): running = the transcript holds a Streaming entry. The Streaming entry rides the OPEN RESPONSE (REMOTE §5.5). Between the model's tool_use and its next response — i.e. the whole time a tool executes — there is no open response, so no Streaming entry, so running=false: settle() marks the last turn settled, no row is live, working() defaults the block to its one counted line, and the intermediate prose paints on the Final bubble as if it were the answer. When the next response opens, everything reopens. Tools dominate wall time, so the operator sees 'all collapsed'. Reproduce with a fixture transcript whose last entry is a Model entry carrying a tool_use block with no ToolResult, and one whose last entry is a ToolResult: both must read as running.

Fix 1 (the bug): derive 'the last turn is running' from the transcript's SHAPE, one query in rows.rs/role.rs: the last turn is running when its last entry is Streaming, or a Model entry with a tool_use block no ToolResult answers, or a ToolResult (the model has yet to answer it). It is settled when its last entry is a Model entry whose blocks hold no unanswered tool_use (the final prose), or a Wounded/Compacted/Delivered-with-epitaph entry. Nothing new on the wire; both routes (committed read, live fold) agree because both feed rows(). Edge: a conversation the operator /stop'd mid-tool has no final prose and reads as running (its working stands open); if the pane can see the row's AgentState::Stopped cheaply (model.convs row for the selected conversation), use it to settle that one case, else leave it open and say so in DESIGN.

Fix 2 (a ruling amendment): in the running turn an intermediate prose (Kind::Said, Speaker::Model, Bubble::Intermediate) stands WHOLE until the turn settles — 'printed directly' — even after further steps follow it; a finished tool call (call + landed result) compacts to its two lines as today; a thinking row compacts when done as today (the operator did not name thinking; the 10-14 ruling's 'etc' stands for it). Once the final prose stands, the whole working folds to its counted line as today. Amend §4.45 item 5's second bullet accordingly and quote today's ruling.

Tests: role::settle / rows() over the three running shapes and the settled shape; working() with a running turn keeps the block open and the intermediate prose whole while a later call is in flight and after it lands; a settled turn folds to one line. Paint-probe or kittest as the existing working tests do (src/ui/chat/tests).
