Found by Parrel landing bl-f021 (2026-07-27): CI green on main, but 'release-plz release' fails twice with stacked causes: (1) crates.io HTTP 400: 'Trusted Publishing does not support the workflow_run event trigger due to security concerns. Please use a different trigger such as push, release, or workflow_dispatch.' The release job is wired on workflow_run (gated on CI success) — exactly what crates.io refuses. (2) The fallback then wants CARGO_REGISTRY_TOKEN, which is deliberately absent (bl-6cfb chose OIDC).

DECIDED (Tumult, architect): keep tokenless trusted publishing; rewire so the publish runs under a PUSH-triggered run while still gating on CI. Mechanism: make ci.yml reusable (add workflow_call to its on: block, alongside its existing triggers) and in release-plz.yml's push-triggered path add a job that  (workflow_call runs INSIDE the caller's run, so the OIDC claim carries trigger=push and workflow file release-plz.yml — the filename crates.io is configured for; DO NOT rename either file). The release job then  that job. Remove/retire the workflow_run trigger arm for the release job (the release-plz PR job and prune job keep whatever triggers they need — audit their conditions so nothing regresses: PR job on push, prune after PR job, manual workflow_dispatch escape hatch stays). Avoid double-running CI per push if reasonably possible (e.g. ci.yml's push trigger vs being called — consider concurrency groups or dropping ci.yml's own push arm in favor of the called instance, so long as PR CI and branch CI still run; weigh simply accepting the duplicate run if dedup adds real complexity — prefer the smallest truthful wiring). A PAT-based workflow_dispatch relay was REJECTED: GITHUB_TOKEN cannot trigger workflow_dispatch runs and the user has not issued a PAT.

Done when: a push to main with green CI results in release-plz publishing the pending version via OIDC (no token), tagging, and cutting the GitHub Release — verified live by the 0.0.1 publish; release-plz.yml's extensive header comments updated to describe the real wiring (they currently document the workflow_run gate and the OIDC claim behavior; keep them truthful, including the filename-immutability warning).
