## Why (found by the bl-1de0 alignment gate, 2026-07-19)

`scripts/smoke.sh` (in the bl-06d5 WIP, commit 42f1660) founds its throwaway harness root by hand:

```
mkdir -p "$HOME_DIR/tools" "$HOME_DIR/skills"
cp "$MODELS_YAML" "$HOME_DIR/models.yaml"
cp "$TOOLS_DIR"/*.json "$HOME_DIR/tools/"
cp -R "$SKILLS_DIR"/. "$HOME_DIR/skills/"
```

ARCH §2.2 makes this exactly one verb's job, verbatim:

> One verb **founds the installation substrate** — the harness root a fresh install has none of. `lernie prime` resolves the config root and data root exactly as every other verb does … and lays down what a ready installation carries: the default global `models.yaml` (§4.2), the `tools/` schema pool and the `skills/` pool (§3.3), and the empty `workflows/` / `workspaces/` directories. … The shipped assets are **embedded in the binary** … **`make install` invokes `lernie prime`** rather than duplicating the seeding, so the verb is the single source of truth for what a ready installation looks like.

The `make install` recipe already states the rule in its own comment: *"the seeding lives in one place (the verb), not duplicated here."*

## Two costs, not one

1. **Single source of truth / front door** (`docs/PRINCIPLES.md`): a second, divergent seeding path that drifts the moment `prime` seeds anything new.
2. **It blunts the smoke test's own purpose.** `prime` seeds from assets **embedded in the binary**; `smoke.sh` seeds from the **source tree** (`install/models.yaml`, `schemas/tools`, `skills/`). So `make smoke` does not exercise the shipped install path — a wrong model id embedded in the binary would be masked by a correct one in the working tree. That is a sibling of the exact bug class (`claude-sonnet-4-7`, bl-3157) this smoke test exists to catch.

## Deliverable

In `scripts/smoke.sh`, replace the four seeding lines with:

```
export LERNIE_HOME="$HOME_DIR"
"$LERNIE_BIN" prime || fail "lernie prime exited non-zero"
```

and drop the now-dead `MODELS_YAML` / `TOOLS_DIR` / `SKILLS_DIR` inputs — the `make smoke` recipe's env block, the three `: "${…:?}"` guards, and the header comment's input list. Net: a smaller script, one input (`LERNIE_BIN`), and coverage of the real path `prime` → `new` → `prompt`.
