There is no release workflow in this repository and that was deliberate: the
first publish is not the shape of a recurring release, and a convenience path
for an irreversible act is how the act happens by accident (AGENTS.md). This
ball is the recurring path, and it is now also the FIRST one — bl-f468 found
that a token publish cannot happen here at all.

WHAT bl-f468 MEASURED, because it changes this ball from a convenience to a
precondition. The registry crate `lernie` is not new: it carries the engine
era's twelve 0.0.x releases, and it is configured to accept **Trusted
Publishing only**. A token `cargo publish` is answered `403 Forbidden` however
the manifest is written — `publish = true` is necessary and not sufficient. A
trusted publisher is ALREADY registered on that crate, from the engine era, and
it names three things that are matched literally against the OIDC claim:
provider GitHub, the repository this tree pushes to, and the workflow FILENAME
`release-plz.yml`. The repository half still matches because the engine's
repository was renamed and this one took the name. So the publisher does not
need registering — it needs a workflow file at that exact name, and renaming
that file breaks publishing until the registry entry is updated.

That leaves the operator two routes and only one of them is this ball's:

- **Relax the registry setting** and publish 0.1.0 by token, as the sibling
  crates' first versions were. One owner act on the registry, no code. It is
  the faster route to the fence and it retires nothing.
- **Build this ball** and let the first publish be the workflow's. Slower, and
  it means the first release under the new name is also the first exercise of
  the pipeline — which is the argument against, not for.

Either way this ball is wanted; the choice is only whether it blocks 0.1.0.

THE STEPS, each severable, in order.

- **The workflow, disarmed at the trigger.** `.github/workflows/release-plz.yml`
  — the filename is not a preference — landing with `workflow_dispatch` only
  and a first job that refuses outright, every other job `needs:` it. Copy the
  shape from thrall bl-d25a: the refusal job stands exactly where the build
  gate goes, so the edit that arms the pipeline is the edit that gives it one.
- **Call the CI gate, do not observe it.** `needs: refuse` becomes `needs: ci`,
  and CI must be a CALLED workflow inside the same run
  (`uses: ./.github/workflows/ci.yml`), never a `workflow_run` trigger: the
  registry refuses OIDC tokens minted under one, so a `workflow_run` gate would
  publish nothing, quietly, forever. `ci.yml` exists here and already runs
  `make ci`, so this is a `workflow_call` entry point on it rather than a
  second definition of green.
- **The permissions and the repository setting.** `id-token: write` on the
  publishing job, and "Allow GitHub Actions to create and approve pull
  requests" on, without which the release-PR job 403s. No long-lived registry
  credential is stored in this repository and none should be — that is what
  trusted publishing buys and it is already half-bought here.
- **The macOS job (bl-9380).** That ball recorded, with the licence text, that
  the seat cannot be cross-built for darwin from Linux: the window links Apple
  frameworks, the frameworks live only in Apple's SDK, and the SDK agreement
  refuses both vendoring it and running it on non-Apple hardware. The operator
  has since ruled that a GitHub Actions macOS runner IS Apple-branded hardware
  in the licence's sense, so the remedy is a `macos` job on this workflow,
  building natively, and nothing in this repository ever acquires an SDK.
  Verify what it produces the way thrall bl-e479 and litany bl-c2b9 do — READ
  the produced Mach-O (architecture, filetype, LC_BUILD_VERSION, signature,
  every LC_LOAD_DYLIB) rather than trusting the build, with a negative
  direction that refuses malformed input first. Signing and notarization are
  not a build-line act and are not this ball's: a downloaded artifact carries a
  quarantine attribute and clearing it is a credentialled act by whoever
  publishes.
- **Arm it**, `push: branches: [main]`.

WHAT IS NOT THIS BALL'S. No upload job for the Linux release binary. No
container image. And no `make publish` — arming the pipeline is not the same as
adding a local convenience for an irreversible act, and the checklist under
AGENTS.md *Before a publish* stays a person's act either way.
