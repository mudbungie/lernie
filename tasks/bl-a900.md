The dispatch commit prunes descriptions/** to the child role's grant relative to what is present in the parent's tree (§3.3 'the fork prunes the snapshot to the role's grant') — but the parent's tree was already pruned to the parent's grant, so child grants are silently ⊆ the dispatch chain's intersection. Tools-list assembly (declaration ∩ availability) then drops the granted-but-descriptorless tool with no diagnostic. Repro (fleet e2e /tmp/claude-1000/-home-mark-dev-lernie/d8b3c251-6d27-458f-a55c-166907ca93db/scratchpad/fleet-e2e/run-20260730-165812-2034594): sensor role granted [slack_read, message], dispatched by a worker whose grant lacked slack_read → steps/<sensor>/001/request.json tools = ['bash','message'] — the sensor's one instrument gone, an ungranted tool present (see the sibling declared-is-not-callable ball). Single-source-of-truth fix: derive the child's descriptions/** from its governing config commit filtered to the child role's grant, never from the parent's tree; at minimum, decline the dispatch loudly when a granted tool has no descriptor to compose. Add a test: child grant ⊄ parent grant composes the child's full toolset.
