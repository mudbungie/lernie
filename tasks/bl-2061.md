Under tarpaulin (`make check`, --test-threads=1) on a loaded box the test `prompt::tool::tests::errors::spawn_retries_past_transient_etxtbsy` (src/prompt/tool/tests/errors.rs:169) fails: `retry budget covers the ~40ms hold: Spawn { name: "blocked", source: Os { code: 26, kind: ExecutableFileBusy } }`.

Observed 5 failures in 6 completed `make check` runs during bl-8c92 (load average 18-27 from ~16 concurrent agent gates on a 16-core box). It PASSES standalone under both plain `cargo test` and `cargo tarpaulin ... -- spawn_retries_past_transient_etxtbsy`, so it is a scheduling-starvation flake, not a logic bug. It blocks every gate on this machine whenever the box is busy.

Mechanism: the test's holder thread opens the tool binary for write, sleeps 40ms, then drops the fd. Production `ETXTBSY_RETRY_BUDGET` (src/prompt/tool/subprocess.rs:34) is 200ms with a 2ms interval. Under load the holder thread's wakeup plus the ptrace-instrumented fork/exec of each retry attempt can consume the whole 200ms before a spawn lands, so the assertion fires.

Two candidate fixes, both needing a decision (neither taken in bl-8c92, which was a pin bump):
- widen the production budget (a real behavior choice: how long a tool spawn retries past ETXTBSY; also forces a longer hold in the sibling test `spawn_surfaces_etxtbsy_after_budget_exhausted`, slowing the suite), or
- make the test's ETXTBSY window deterministic rather than wall-clock (the current 5x margin is not a margin under starvation; shortening the hold does not fix a starved wakeup).

Also worth noting: two gate runs during bl-8c92 died to an external SIGTERM ('make: *** [Makefile:54: coverage] Terminated') ~13 min in, even under `setsid`. Source unidentified; possibly a stray process-group kill from a concurrent agent. Separate hazard, same symptom class (gate unreliability under agent fan-out).
