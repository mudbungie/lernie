Operator report 2026-08-01: double-click-drag should extend selection by word
boundaries (triple-click-drag by lines); egui reverts to character granularity.
Investigation (2026-08-02, select-fixer) established: the window owns none of
the selection path (all stock `egui::Label` / `TextEdit`), egui has never
implemented this at any version, labels cannot be fixed from outside egui
(`LabelSelectionState` has no public range access), and egui #2550 has been open
since 2023-01 with no PR.

## DECISION (operator, 2026-08-01): Path A — upstream it. EXECUTED.

Upstream PR filed: **https://github.com/emilk/egui/pull/8370** (draft → ready
after CI), announced in
https://github.com/emilk/egui/issues/2550#issuecomment-5154053083, from fork
`mudbungie/egui` branch `word-drag-selection`.

Root cause found during implementation: egui counts clicks only on pointer
*release* (`PointerState`), so at drag-start nothing knows the gesture began
with a double-click — that's why the feature never existed. The PR: (1) computes
the would-be click count at press time (`pub(crate)`); (2) `TextCursorState`
selects word/line on the second/third press and keeps it as the drag anchor;
drag selects `union(anchor, unit-at-pointer)`; (3) `LabelSelectionState` carries
the anchor across passes for cross-label drags. Unit tests + 5 kittest
integration tests (`tests/egui_tests/tests/test_text_selection.rs`), all local
checks green (fmt, clippy incl. workspace, docs -D warnings, typos, lint.py,
full egui + egui_tests suites; the 1-2px `visuals/{button_image,radio}` snapshot
diffs are pre-existing on that GPU, confirmed against clean upstream).

Assessment 2026-10-31 (not done; unclaimed). A release now carries the fix: egui 0.37.0, published 2026-10-15, is 34 commits past merge 9c7bf826 and its notes list #8370 ('Add double-click-and-drag and triple-click-and-drag text selection'). So the bump is live, but 0.30 -> 0.37 is seven minors and the breakage is a multi-day port, not a dep bump. Measured on a worktree with eframe/egui 0.37 and egui_kittest =0.37.0 in Cargo.toml plus 'cargo update -p egui -p eframe -p egui_kittest' (lockfile resolves cleanly): 'cargo check --all-targets' fails the lib with 100 errors and the lib test with 280, across 93 source files, before any integration test is compiled. Classes, by count: (1) 77 '&Context vs &mut Ui' mutability mismatches - 0.34 replaced Context::run with Context::run_ui and eframe App::update with App::ui, so every pane entry point and every test that drives a Context changes signature; (2) 66 uses of Id::new, deprecated in 0.37 for Id::unique / IdSalt - a semantics choice per site (globally unique vs locally salted), not a rename, and warnings=deny makes each one an error; (3) egui_kittest Node API is gone as this tree uses it - role, label, id, is_hidden, bounding_box, toggled, author_id all missing - so src/snapshot/* and every AccessKit-walking test are rewritten against the new query API; HarnessBuilder::build_state and Harness::press_key also gone; (4) removals/renames: Frame::none -> Frame::NONE (12), Margin now i8 (6), SidePanel/TopBottomPanel -> Panel (7), Context::style/style_mut/set_style moved (11), screen_rect -> content_rect (4), Visuals::window_rounding/menu_rounding -> CornerRadius, Options::line_scroll_speed removed, RawInput::modifiers removed, scroll_area::State::offset private, PanelState::rect gone, text cursors take ByteIndex, WidgetType -> Role with renamed variants. Two further costs are not compile errors. (a) 0.34 removed the accesskit FEATURE and always links accesskit: the Cargo.toml dev-dependency paragraph that keeps accesskit out of the released seat ('a product decision nobody has taken') is void at 0.37 - the bump takes that decision, and the operator should rule on it before the port lands. (b) kittest 0.37 fails any test whose input widget has no accessible name and panics by default on a missing glyph (MissingGlyphPolicy), so the harness may need naming on every TextEdit and a font policy. Also to carry: deny.toml - the Ubuntu font licence now has the SPDX id Ubuntu-font-1.0 (replace LicenseRef-UFL-1.0, which is what fails 'cargo deny check licenses' today), BSL-1.0 is no longer encountered, and all four advisory ignores (RUSTSEC-2026-0192, 2024-0436, 2026-0194, 2026-0195) stop matching and should be dropped per their own comments; new unmaintained advisories arrive on zbus_names/zvariant/zvariant_derive under the AT-SPI stack. Recommend splitting: one ball for the operator ruling on accesskit-in-the-binary, then the port itself (possibly stepped 0.30 -> 0.34 -> 0.37, since 0.34 holds the Ui/Context and font-engine changes). Nothing from this assessment was committed; the worktree edits were only the two manifest lines and the lockfile.
