Gap surfaced by bl-4ce8: ARCHITECTURE §2.9 step 3 specifies the executor catches SIGTERM and, for a child, deposits its result message with a 'stopped' epitaph before exiting (the deposit is executor-side — 'Return is not a verb'); bz still dies instantly so the missing-end stop signature on response.json is preserved (independent writes, neither disturbing the other). The shipped run_exchange has no in-process SIGTERM handler — stop is currently external SIGTERM via lernie stop with no deposit. Epitaph::Stopped and inbox::deposit_result (bl-4ce8) already exist and are unit-tested; this ball wires the handler: catch SIGTERM in the executor, deposit via deposit_child_result (root = no-op), exit. Constraints: the handler must not swallow the signal for the process group (tool subprocesses and bz still die per §2.9 steps 1-2); the deposit must be async-signal-safe in practice (flag-and-deposit-outside-handler is fine — the §2.9 contract is 'on its way out', not 'inside the handler'). Test with real signals (the repo has hook-env/GIT_DIR test traps — see AGENTS/test conventions).
