## Scope
The platform's stated purpose — "Experiments are config diffs, measurable against a task suite" (§1 Testability) — is now measurable: the evaluation layer (§9) has shipped.

## What "eval" strictly means here — DEFINED (2026-07-17)
The term of art is now pinned. **eval** / **evaluation run** = *(experiment × suite × N)*: run one workflow-config variant against the fixed task suite N≥5 times, machine-check each task's success criterion (a `check` script, exit 0 the sole pass signal), aggregate pass@1 (mean-of-means, 95% Wilson CI) and pass@5. It evaluates HARNESS CONFIGURATION, holding tasks and models fixed. It is NOT: model-capability benchmarking, per-response LLM-as-judge grading, or online/production monitoring (§8's metrics own that). Operational-definition home: ARCH §9.1/§9.3. Term-pin + field disambiguation: docs/TAXONOMY.md §7 (lernie's stance), cross-referenced both ways, not duplicated — landed this task (the docs gate).
