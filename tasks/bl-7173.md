ARCH §2.1 bans "**call**" without a qualifier "*as a term for an interaction with a model, tool, or API*". The bl-1966 carve-out sanctions the programming sense alone — "*Call site, callback, callee, function call, system call … stay as they are*". Three sites use the banned sense for a tool call:

- `docs/ARCHITECTURE.md` §3.3 (the `cd` built-in): "This is a *fact about the agent*, not a **per-call** parameter and not shell state".
- `src/install/tests/toolspec.rs:135` and `:138`: "the cwd is not a **per-call** …", "so a **per-call** override would be a second home for it" — the test comment restating the same reasoning.

The architecture violating its own ban is the worse half: §2.1 is where the rule is read from, so a reader who checks the rule and then reads §3.3 gets contradicted by the document that made the rule.

Fix: "per-tool-call" (the qualified form §2.1 names) at all three, or reword to "a parameter of the call" only where the programming sense is genuinely meant — it is not, here.

Found while fixing the same violation in `schemas/tools/dispatch.json` ("Per-call goal text" → "Per-dispatch") under bl-a4d5, and split out rather than swept in: that ball was about the parent/child relationship, and the `cd` working directory is a different subsystem.
