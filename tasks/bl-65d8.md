Deliverable: edits to `docs/PRINCIPLES.md`, `docs/ARCHITECTURE.md`, `docs/TAXONOMY.md`. Living document — this body records the decision; **the docs are the artifact** (a closed ball has no file; nothing here survives close).

## The defect

`docs/ARCHITECTURE.md:166` (§2.3 step 4) gives Completion **three** arms: *"A terminal event: final response, stop (§2.9), budget exhaustion (§6)."*

Step 5 (`:167`) fires on only one of them, because `:330` (§2.9) says: *"A stopped agent deposits no result: a stopped child’s parent derives `{status: stopped}` through `check`/`await` (§2.5)."*

So `await` is not a waiting primitive. It is a **fallback for the two terminal arms that skip step 5** — §2.5 (`:252`) says so outright: `{status: stopped}` / `{status: budget_exhausted}` are *"the fallback for children that die without returning."* That is a special case, and the reframe is to delete it.

## The fix: make step 5 total

**Every terminal event deposits a result message.** Final response, stop, budget exhaustion, hard crash. The inbox becomes the only return path, revival-on-deposit (§2.11) wakes the parent in every case, and `await`/`check` have nothing left to observe.

The parent never blocks. It dispatches, terminates its step, goes quiescent, and is revived by the deposit. **Waiting on a child is the same act as waiting on the user** — the bidirectional completion of §2.5’s *"From the child’s perspective, its parent is indistinguishable from a user."*

Model-facing verbs reduce to **`dispatch`** and **`message`**.

## Return is not a verb — the load-bearing automation

The deposit is **executor-performed**, never a model tool call. An agent does not decide to return; it decides it is *done*, and return is what the harness does with done. The model has no return verb, so it cannot forget to call one.

This is the whole stall-prevention mechanism, and it is why lernie does not need what other harnesses need. A harness that makes the child’s result the tool’s *return value* (Claude Code’s Agent tool; pi’s `subagent()` extension) must instruct the model to close out explicitly — and then pays for it twice: with **truncation limits** (pi caps results at 200KB / 5000 lines, because the result must fit the parent’s context) and with **stalled parents** when the model simply neglects to call the close-out tool. lernie’s result rides its own channel plus a work-product diff, so the terminal response can just *be* the terminal response, and no instruction is needed for it to arrive.

Corollary for the implementer, restated below: this must not be built by synthesizing a `message` tool call.

## Epitaph is the union — and it is a missing field

Not the exception-set. If "epitaph" named only the no-terminal-response cases, it would be a *kind* of message, code would branch on the kind, and the special case we just deleted would return through the vocabulary door.

Under the union it names something genuinely absent today. §2.6 currently pins two things in the result message — *"the child’s terminal response and … the sha of its branch tip at return"* — and that is sufficient **only because `await` supplies the third**. Delete `await`, and a budget-killed child, a stopped child, and a crashed child all deposit a message with an absent terminal response: the parent sees three empty messages and cannot tell them apart. Information loss.

So the manner-of-ending rides *in* the message, and is **pinned** for the same reason §2.6 already pins the terminal ref — *"so later revival of the child (§2.4) cannot move what the parent was offered."* A revived child’s live classification flips from `stopped` to `quiescent`; the parent must still see what it was handed. §3.5 (`:484`) is a live query; this is a frozen fact.

**Every result message carries three fields:**

1. **terminal ref** — always (already specced, §2.6).
2. **epitaph** — always. The pinned manner of ending: final response / stopped / budget-exhausted / died.
3. **terminal response** — present iff the agent spoke.

Code branches on the epitaph’s **value** (a parent should reason differently about "budget-killed at 60%" than "finished") — never on the message’s **shape**. One primitive, one delivery path, one work-product transfer, three fields, one sometimes empty.

## No watcher is needed

§2.11 (`:373`) forbids one: *"No abandonment, no takeover, no watcher left behind."* It is not needed. Decomposing the arms:

| Terminal arm | Catchable | Who deposits |
|---|---|---|
| Final response | — | Executor, step 5 (already specced) |
| Stop (user/cascade/timeout) | SIGTERM — yes | Executor, in the handler |
| Budget exhaustion | Harness-issued — voluntary | Executor, before exit |
| SIGKILL / OOM / panic | No | The §8 sweep |

Three of four arms need no observer — just "deposit on your way out." Only hard crash needs one, and §8 (`:812`) **already enumerates exactly the right candidate set** for the silent-death metric: branches with no live executor that *"either died mid-work … or, for a child, never deposited a result message."* Today it counts them. Make it deposit for them. Same query, one more action, zero new mechanism.

Sender on a swept deposit is the **child**, not the harness — the parent’s inbox is sender-namespaced and the "a message from the child exists" derivation depends on it. The sweep is the scribe, not the author.

## Scope

**`docs/PRINCIPLES.md`** — two edits, and this is where the concept durably lives:

- **`:38` "Tools return synchronously; async rides on handles" is falsified by this ball** and must be rewritten. It currently reads: *"Long-running work surfaces as a handle; `await(handle)` and `check(handle)` derive its status, and the result itself arrives as the child’s result message (§2.5, §2.6)."* The first clause survives (the wire genuinely requires paired `tool_use`/`tool_result`); the handle-status machinery does not. Async now rides on the **inbox**: a dispatch returns the child’s *address*, not its result, and there is nothing to await — a parent waiting on a child is parked exactly as a root agent is parked waiting on the user, and a deposit revives it.
- **New principle: "Return is not a verb."** Termination *is* the return; the executor deposits, the model never calls. See the section above — including why this is what makes lernie immune to the close-out stall and the truncation cap that call/return harnesses pay.
- `:18` "Symmetry of dispatch" already says *"every sender is indistinguishable from a user for the recipient’s whole life"* — extend it to the parent’s side: a child is indistinguishable from a user *to the parent*, too. Both are senders; parking is parking.

**`docs/ARCHITECTURE.md`**

- §2.3 step 5 — becomes total (every terminal event deposits).
- §2.5 — the `await` / `check` paragraphs delete.
- §2.6 — the result message gains the pinned **epitaph** field.
- §2.9:330 — inverts: a stopped agent deposits, with a `stopped` epitaph.

## Explicitly out of scope

- **Code deletion** — bl-2ca1 (`await_tool/`), bl-4ce8 (`merge/`). This ball is the doc.
- **The inbox itself** — bl-4298. It does not exist in code; this ball specifies what it must carry.
- **Fan-out join.** Each deposit wakes the parent separately, ~2 extra model calls on a 3-way fan-out. Accepted: per-return reprompting is usually what you want, and it is what lets the parent react to child 1 before child 3 lands — §2.5 already concedes blocking `await`’s flaw (*"a parent parked in a blocking `await(handle)` has no step boundary until that await resolves"*). If it ever bites, the join is a §6 workflow binding — config, not schema.

## Trap for the implementer

Do **not** synthesize a `message` tool call to perform the return. It would put a `tool_use` block in `messages/NNN-assistant.json` that the model never emitted, breaking §2.3’s *"exactly as the step’s authoritative attempt segment emitted them"* (`:185`), and it would un-terminate the step (`:166`). The deposit is executor-side, outside the transcript. `message` stays the tool an agent calls when it *chooses* to send.
