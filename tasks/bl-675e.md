Third bump in the release chain, after bl-d774 (2 -> 4) and bl-e6ee (4 -> 5).
The handshake is fail-closed with no negotiation (REMOTE §3), so a seat one
integer behind cannot dial at all.

## What moved (REMOTE §9.13, upstream bl-23bd)

**`reply/providers` rows gained `effort` and `priority`, two required
booleans** — which tuning knobs that provider row actually takes. Read as
columns out of the adapter's own provider listing and re-derived nowhere,
because only the row can see its own decline of a dialect key. They **gate a
control, never a write**: a row taking neither knob hides both selectors and
refuses no gesture, and they are required rather than optional precisely so an
unanswered question can neither block a row nor silently grant it a control.

Two new request ops ride along — `/effort` and `/priority` — and upstream is
explicit that they cost nothing: a new op is a new spelling in an existing
vocabulary and a peer that has not heard of one refuses it in band, by name.
**One bump, for the row.**

The vocabulary is deliberately the operator's, not a provider's: `effort` and
`priority` because that is what the config says and what a person means, never
a dialect's own spelling.

## What this seat owes

`PROTOCOL` 5 -> 6, and the corpus re-vendored so the stamp check stops failing.

**Then verify, never assume, where the moved shapes land.** Two questions, both
answerable from this tree:

- **`reply/providers`** — does any pane here read provider rows? If a model-pick
  or login surface exists, the booleans go where its own docs say they belong;
  if the shape is in `corpus/unreadable/` because nothing paints it, it stays
  there and the correct amount of new paint is none (DESIGN §4.9).
- **the two new request ops** — the request direction has no `Read` class, so
  they must still decode as gestures this seat can ROUTE, and by the address
  their own signature carries. That is where a miss costs something: a
  gesture routed by a slot the seat does not look in goes down the wrong
  channel, silently. `src/verbs/tests/corpus.rs` asks this against
  `shapes.json` as a second opinion; check also whether `UNEMITTED`'s counts
  move, since they fail closed until the reason is rewritten.
