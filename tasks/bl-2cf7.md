Seven `control`-classed reads with no interactable here — `agent`, `steps`, `step`, `files`, `rail`, `governing`, `inbox` — and `fork`, which is an act but cannot be composed without two of them.

bl-213c built the conversation's ACTS half and left this. The seam is the reply layer, not the layout: `stop`, `interrupt`, `retarget` and `delete-agent` each answer a captured run, which is a kind this seat already decodes and already paints, so a control firing one of them is answered. Every read above answers a kind `src/reply` has no decoder for and the vendored corpus carries no answer fixture for, so a control firing one today earns `Notice::Unreadable` — a button that reliably fails.

So each of the seven owes three things and not one: a typed reply in `src/reply`, an answer fixture in the vendored corpus, and a pane that paints it. `fork` owes none of those and still cannot land: its `from` is a commit off the rail and its `role` a name off the config lineages, and a control demanding two opaque strings an operator has no way to discover from this seat is a control that only looks actionable. It lands with the rail.

Exemption rows in `parity.toml` cite this ball until the pane does.
