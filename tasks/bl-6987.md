## CENSUS — every wall-clock construct in src/ + tests/ (grep: Duration::from_*, thread::sleep, Instant::now, deadline, elapsed, timeout; also SystemTime::now, crates/, tests/)

### UNSAFE, fixed here (6 sites)
1. src/prompt/tool/subprocess.rs ETXTBSY envelope — was `Instant::now() < deadline` with a 200ms Duration budget. Converted to attempt count per bl-edf6: `ETXTBSY_RETRY_ATTEMPTS: u32 = 100` x 2ms interval = same ~200ms idle-machine envelope, longer under load (which is when the fork/exec window stretches). `SpawnArgs.etxtbsy_budget` and the `with_etxtbsy_budget` seam (spawn.rs) are now u32 attempt counts.
2. src/prompt/tool/tests/etxtbsy.rs — all three tests conformed: fixture self-exec envelope is a 10_000-attempt count; retry-arm test injects 1_000_000 attempts (was 30s); give-up test injects 3 attempts against a permanent hold — retry-arm coverage is now structural (exactly 2 sleeps every run), was probabilistic under a 1s deadline.
3. src/prompt/tool/tests/cascade.rs sigterm_inside_deadline test — stop flag was flipped after sleep(150ms), racing the fixture shell's `trap` install; under load SIGTERM could land pre-trap and the default disposition killed the fixture (wrong-arm failure). Now the fixture touches `ready` in its cwd AFTER `trap`, and the flipper polls that marker (count-bounded, MARKER_RETRIES=12_000). Deadline raised 2s→60s (never expires on the pass path; the tool exits on TERM).
4. src/prompt/tool/tests/cascade.rs sigkill_after_deadline test — same trap-install race, same marker fix. The 250ms deadline stays: with the trap provably installed, expiry is the only possible outcome (handler never exits), so load can only delay, not flip, the verdict; the elapsed>=deadline assert is a lower bound (load-safe direction).
5. src/prompt/stop/cascade.rs real_signaler_kill_uncatchable test — kill(-pid, SIGTERM) raced the `trap '' TERM` install (spawn returns after exec, but the trap builtin runs after that); the settle was a sleep(50ms). Now the fixture echoes `ready` post-trap on piped stdout and the test blocks on that line; the sleep is gone (with the trap provably installed, TERM structurally cannot kill it).
6. src/prompt/compactor/checkpoint/tests.rs — two `state()` tests derived expected elapsed from "both commits land in the same wall second" (assert <=1) or a lower bound (>=42). Two real `git commit` runs under load can straddle seconds. Now `now` is anchored on the reference commit's own committer time read back from git (now_of while it is HEAD), and both asserts are exact equalities (==7, ==42).

Plus margin alignment (same class, e2e): src/e2e/stop_cli.rs mock SSE delay 30s→120s and tool `sleep 30`→`sleep 120`, matching stop_children.rs's established 120s hold — the hold is the non-verdict side of a two-clock race against evidence-anchored local work; sized so no plausible stretch outruns it.

## DETERMINISM EVIDENCE
Synthetic load: 40 CPU spinners on the 16-core box, ambient sibling gates on top; load avg 65-85 throughout (above the bl-9300 bar of 30+). Touched tests (24: etxtbsy x3, tool cascade x3, stop cascade x7, checkpoint x10 incl. the 2 fixed, e2e stop_cli x2, minus overlaps): **30 consecutive passes** (runs 11-40), plus 12/12 of the e2e stop_cli pair alone. One pre-fix-verification anomaly (run 1 of the first probe batch): the whole test binary died by SIGKILL with both e2e stop_cli tests in flight; NOT reproduced in 42 subsequent runs. Forensics (bpftrace kill tracer over runs 11-30): no in-tree sender can target the test binary — stop discovery accepts only leader pgids (bl-5f0c), `lernie stop` refuses its own group (getpgrp vet), every in-process kill site targets a direct child or its setpgid'd group while unreaped; the tracer did record third-party `sh` processes firing kill -9 at process groups on this shared box (concurrent sibling agent sessions), which is the credible killer. No kernel OOM in the window (journal checked). Verdict: external to the repo; will re-flag if it recurs under the landed tree.
