The mint draws **one lowercase word** from the 541-word embedded pool
(`src/workspace/agent_name/mint/words.txt`). A single common noun does not read
as a *name* in the surfaces that carry it — a yog conversation row, a `lernie
list` line, an id's hyphenated descent — it reads as a word that happens to be
there. **Two words in PascalCase** carries the naming intent in its own shape.

Operator ruling, 2026-08-16: minted agent names become two words, PascalCase
(`PeachHollow`, not `peach`, not `peach-hollow`).

## What is lawful today, verified

Uppercase and multi-word names are already legal — no validator has to change:

- `src/name.rs::is_component` — "True iff `name` addresses exactly one path
  component: non-empty, not `.` or `..`, and free of `/`, `\`, and NUL."
- `src/workspace/agent_name.rs:162` (`require_available`):

      if !crate::name::is_component(name) || name.chars().any(char::is_whitespace) {
          return Err(Unavailable::Malformed(name.to_owned()));
      }
      if name.split('-').next().is_some_and(is_id_timestamp) {
          return Err(Unavailable::IdShaped(name.to_owned()));
      }

  PascalCase has no whitespace, no separator and no leading timestamp, so it
  passes all three arms. It is also strictly *better* against the hyphenated
  descent `<a>-<b>-…` (ARCH §2.3): a PascalCase name contains no hyphen, so a
  name can never be misread as two descent segments.

## The shape of the change

`mint_from` is a pure scan over an index space with wraparound, and that is
worth keeping exactly as it is:

    let start = (rng.next_u64() % pool.max(1) as u64) as usize;
    for step in 0..pool {
        let name = words.get((start + step) % pool)...
        if !occupied.contains(name) { return Ok(name.to_owned()); }
    }
    Err(MintError::Exhausted(pool))

Prefer widening the **index space** over adding a second draw: pool becomes
`n * n` (or `n * (n - 1)` if a word may not pair with itself), index `i` maps to
`(i / n, i % n)`, and the scan, the purity, the single-draw property and the
`Exhausted` bound all survive unchanged. One RNG draw per mint stays true, so
every scripted-draw test keeps its meaning. Do not reach for a second wordlist —
541 words squared is ~292k names, which is not the constraint.

Attack it before committing: the pair space is not uniform under the scan (a
collision walks to the next *second* word, not the next pair at random), which
is the behaviour the one-word mint already had and nobody wants randomness
guarantees from it. Say so in the doc rather than adding a second draw to fix a
non-problem.

## What must move with it

- `mint.rs`'s module header — "a single word from the embedded wordlist" — and
  the `mint` fn doc, "the first single word not in `occupied`".
- `words.txt`'s own header: "541 words. One is drawn as an agent name".
- ARCH §2.3 wherever it states the single-word shape. **Read it first and fix
  the doc rather than deviating from it.**
- `mint/tests/corpus.rs` pins the pool by count and digest — the wordlist itself
  is UNCHANGED, so that pin must still pass byte-for-byte. If it doesn't, the
  change touched data it had no business touching.
- Case-insensitive filesystems (macOS, Windows) are the one new hazard: the
  occupied set is an exact-match `HashSet<String>`, so `PeachHollow` and
  `peachhollow` are two names to the mint and one directory to the filesystem.
  PascalCase-only output means the mint can never produce that pair itself; an
  operator-supplied name still can, which is `require_available`'s existing
  behaviour and NOT this ball's scope — note it, do not widen.

## Downstream

both preview and fire, and pins no literal minted word in any test — checked
across `src/` and `tests/`. So yog needs a version bump and nothing else. File
that as its own ball in yog when the release lands; it is not a subtask here.
