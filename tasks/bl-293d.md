Round 2, lane comparator. Steal-list item 1 of 3: the ACTIVITY LINE.

Companion to bl-183b, which already rules that `lernie follow` must render the tool window yog bl-5305 added to the frame. This ball is the SHAPE of that rendering, taken from the comparator that does it best, so the two can land together.

## The comparator, verbatim

`hermes-agent 0.15.2`, driven on this box against a `bz --serve` ingress, one query — "In calc.py rename add to plus and keep the same body." Its whole activity rendering was these six lines, printed as the run happened:

      ┊ 🔎 preparing search_files…
      ┊ 🔎 find      calc.py  1.0s
      ┊ 📖 preparing read_file…
      ┊ 📖 read      ./calc.py  0.4s
      ┊ 🔧 preparing patch…
      ┊ 🔧 patch     ./calc.py  0.4s

and it closed with

    Session:        <id>
    Duration:       22s
    Messages:       8 (1 user, 6 tool calls)

Four conventions are doing the work, and each is separable:

1. **A quiet gutter glyph** (`┊`) marks every line the harness wrote about itself, so the model's prose and the harness's narration never have to be told apart by eye. It is one character and it is not a box.
2. **Two rows per call, and the first is the DISPATCH.** `preparing read_file…` is printed when the call goes out; `read ./calc.py 0.4s` replaces the wait with the outcome. That is exactly the shape yog bl-5305 put on the wire — `input.json` lands before dispatch, `output.json` on capture, `exit_code`'s presence is the status — so lernie already receives both transitions and needs no new field to print both lines.
3. **A verb column, a subject column, and a duration.** Not the tool's name and its JSON input: the tool's KIND (`read`, `find`, `patch`, `$` for a shell) and the one argument that identifies what it touched, aligned so a column of calls scans vertically.
4. **A cost line at the end** naming duration and the count of tool calls, so "what did that turn do" has a number.

## What lernie prints today

`src/render/walls.rs::follow` folds `thinking` and `text` and, on a content-free frame, prints `…` plus a delta label. Prose and a heartbeat. Round 1 measured the same thing from the other end: an operator watching an agent administer two boxes saw a thinking marker and two sentences while eight commands ran.

## Proposed rendering for lernie

Same two transitions, no emoji required (a terminal that cannot draw them prints boxes, and the glyph is not the idea):

    ┊ bash     hostname && uptime                       …
    ┊ bash     hostname && uptime                    0  0.4s
    ┊ box2     bash · systemctl restart nginx           …
    ┊ box2     bash · systemctl restart nginx        0  1.2s
    ┊ patch    src/roman.py                          0  0.1s

- The gutter is `┊` (or `|` when the locale cannot); the model's own prose keeps the left margin, unmarked.
- Column 1 is the tool. A ROUTED call splits `<client>_<tool>` — REMOTE §5.1 guarantees that shape — and prints the machine first, because on the follow lane the question is which box this is happening on.
- Column 2 is the subject: for `bash` the command line, for a file tool the path, elided in the middle with an explicit mark, never silently.
- Column 3 is the exit code once `exit_code` is present, blank while absent. Its presence IS the status, so a live call needs no spinner — the trailing `…` is enough.
- Column 4 is elapsed, computed from the two transitions' arrival.
- On rest, one summary line: elapsed and the number of calls.

## Severity

p4. Nothing is broken; this is the difference between watching work and watching a cursor. It is cheap because the frames already carry every field it needs.
