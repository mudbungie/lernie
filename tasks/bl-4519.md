Operator 2026-10-31: 'scrolling in the chat is way too slow/precise. It should scroll maybe three times faster.'

Today: settings::WHEEL = 100 points per notch, installed as egui Options::line_scroll_speed (src/ui/theme/visuals.rs). That option scales ONLY MouseWheel events in Line units (a clicky mouse wheel). A touchpad (this is a Wayland laptop with no xinput) delivers Pixel-unit deltas, which egui passes through untouched — so for a touchpad the knob has never done anything, which fits 'too precise'. The operator's stored settings carry no wheel value, so the default governs.

Fix: (1) raise the default to three times today's: WHEEL = 300. (2) Make the one knob govern every scroll delta: in eframe::App::raw_input_hook on Seat (src/main.rs), scale each Event::MouseWheel's delta — Line units stay the toolkit's line_scroll_speed path (set to the knob), Pixel/Point units are multiplied by knob / 100 (so the knob keeps its meaning 'points per notch' and a touchpad moves 3x at the default). One knob, one fact; DESIGN §4.46 item 1 amended to say the knob scales both units and why ('a notch and a swipe are both the hand asking for distance'). Keep the settings pane's wheel row as is (its range may need widening to admit 300+; check knobs.rs). Tests: a Pixel-unit wheel event through the hook comes out scaled; a Line-unit one is untouched by the hook; the default is 300; the knob's serialised absence still means the default.
