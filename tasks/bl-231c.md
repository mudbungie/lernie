Requirement from yog phase-2 (crate adoption): yog intends to link lernie as an exact-pinned Cargo dependency instead of shelling to the binary, with the binary remaining as the agent/human tool plane.

USER MANDATE (2026-07-19, supersedes 'likely' hedges below): the CLI interface and the library interface must be LITERALLY IDENTICAL — exact parity, both directions: nothing exposed by the lib may be unavailable via the CLI, and nothing the CLI offers may be missing from the lib. The parity must be ENFORCED BY CI/CD (a check that runs under make check, i.e. pre-commit hook and GitHub Actions both).

1. ARCH §3.4/§3.5 currently declare 'no library API surface / no library port'. DESIGN-FIRST: amend ARCHITECTURE.md (§1 overview sentence, §3.4, §3.5) to define the library surface as *the same control-plane surface with a second binding*: the clap command definition (per-verb Args structs + the Command enum) moves into the library; the lernie bin becomes a thin argv shim (parse -> process-global effects -> lernie run -> perform Outcome). A library consumer constructs the same Args structs and calls the same run functions — parity of verbs and parameters by construction. Everything else in the crate goes non-public. Promise: pin-exact, no semver stability at 0.x (brazen posture).

2. The driver/successor exec baton: advance execs the successor and message/prompt detached-spawn 'lernie advance', resolving the current binary. Parametrize the successor/driver target (injected into the effects/deps; bin injects current_exe, an embedder injects its own re-exec target) so a linked lernie never hard-depends on a lernie binary on PATH mid-loop.

3. Enforcement: by-construction covers verb<->entry parity; the residual drift (extra pub items) is caught by a parity test that walks the crate's actual public surface from src/lib.rs (syn dev-dep) and asserts it is exactly the sanctioned command-surface skeleton, and that clap's introspected verb set (CommandFactory) is bijective with the surface modules. Runs as an ordinary cargo test -> covered by make check -> pre-commit + CI. No nightly, no extra binary tools.

Consequences to absorb: integration tests that import crate internals (bash_tool, read_file_tool, template, action_dsl, workflow_yaml, providers_split_integration) move in-crate as #[cfg(test)] modules or re-target the surface; gen-schemas (see bl-a953, claimed: moving to example) needs schemas generation reachable without widening the public surface — coordinate at merge.

Design deliverable is the ARCH amendment; implementation follows it.
