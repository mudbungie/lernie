The window opens with whatever icon the desktop invents for a client that names none. That is cosmetic, and it is also the ball AGENTS.md already anticipates: lernie's tracked-binary allowlist is EMPTY, deliberately, and the note beside it says the window will want an icon and that the ball adding one adds the first entry — with the test that regenerates it and checks it byte for byte.

So this ball is two things and the second is the interesting one:

- An icon, and the platform facts that decide whether it is seen at all. Wayland has no protocol for a client to set its own window icon, so the toolkit's icon call reaches X11 and nothing else; what a Wayland desktop reads is the application id against a desktop entry. Upstream pays for this with a feature flag on its winit layer and a `.desktop` file, and the ball's first duty is to say which of those the seat needs rather than copying both.
- The allowlist entry, and it is not a line of config. `scripts/leak-rules.sh` rejects unreadable content rather than skipping it, because a binary is the class most likely to carry a dump, and `BINARY_ALLOWED` is spelled as the empty set on purpose. An entry without a test that regenerates the file and compares it byte for byte is not an allowlist entry; it is a hole. The test comes with the file or the file does not land.
