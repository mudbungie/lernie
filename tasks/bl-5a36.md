That child's first model request (steps/<child>/001/request.json) contained the parent's ENTIRE dialog as its own conversation - including the user-role message 'spawn a subagent to analyze...' - because the fork inherits the parent's messages/** and the dispatch commit's trim never removes them. The unsettled-tail prune (bl-4231) deletes the parent's model-output entry carrying the dispatch tool_use - i.e. exactly the evidence that the spawn already happened - so the child sees an unanswered user instruction 'spawn a subagent' outranking its parent-sent goal message, and obeys it. Every generation repeats: 4 generations in ~9s (22:37:11/14/17/20) until the operator stopped it.

Mechanism, file:line: src/prompt/dispatch/step_commit.rs trim_to_context stages the dispatch commit's trim (control files, descriptors-to-grant, unsettled tail, name) but leaves the fork point's branch-scoped dialog - messages/**, summary/**, skills/** - in the child's tree; assembly is a pure function of the tree (ARCH 5.1) and the transcript composes unconditionally (5.2), so the parent's dialog IS the child's opening context.

ARCH 2.2 already states the invariant the code misses: goal.md, soul.md, name, summary/, messages/ 'are written per-branch, and they never enter any other branch's tree'. The transfer filter enforces it child-to-parent (transfer.rs CONTEXT_EXCLUDES); nothing enforces it parent-to-child at the fork.

Fix: add the inherited-dialog removal to trim_to_context - the fork point's messages/**, summary/**, skills/** leave on the dispatch commit - EXCEPT for the compactor role, whose subject IS the dispatching branch's history (ARCH 2.7: 'its worktree carries that branch's transcript... and it is composed from that tree'; the summary chain must stay visible or a superseding summary destroys it).
