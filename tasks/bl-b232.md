Round-1 daily lane. lernie 0.1.30.

A malformed `ask` envelope prints one line of diagnosis and then the entire `lernie help` output — about 110 lines, the full 61-verb table and all four door pages — to stderr.

    $ lernie ask '<truncated json>'
    lernie: not JSON: EOF while parsing a value at line 1 column 0
    lernie 0.1.30
    ...
    [the whole help, including THE NAME HAS TWO ERAS, the 61 verbs, and the four pages]

The diagnosis line is good and precise. What follows buries it: on a terminal the error scrolls off the top before the operator's eye reaches it, which is exactly backwards for a message whose whole value is the byte offset it names.

`ask` is the verb an operator uses in a loop while composing an envelope by hand — this lane spent a day there, because `start` cannot reach the path rung — so the malformed case is the COMMON case for this verb, not the exceptional one.

A refusal on a KNOWN verb behaves well by contrast: `lernie help prepare` answers "lernie: no word named \"prepare\" — `lernie help` lists every one" and then also prints the whole help. Same pattern, same problem: the sentence already tells the reader how to get the list.

Expected: print the diagnosis and a one-line pointer (`lernie help` / `lernie help ask`). The full page is what `help` is for.

Severity p3, and it is two lines of code.
