Operator 2026-11-06: the earlier 'ape Hermes' directive meant the Hermes **Desktop** GUI (hermes-agent repo, apps/desktop: Electron shell + React renderer on assistant-ui, talking to a headless `hermes serve` gateway over JSON-RPC/WebSocket), not the TUI that bl-7859 / DESIGN 4.42 ported.

## What was done
- Found it: upstream apps/desktop, public preview since 2026-06; `hermes desktop` builds the unpacked Electron app from a source install.
- Updated the local source install v0.21.7 -> v0.23.0 (`hermes update`), built with `hermes desktop --build-only`, ran it on the Xvfb probe seat (:99) against the real Hermes home, drove it by mouse (xdotool) and captured ~30 screens with ffmpeg x11grab.
- Sent one live tool-using turn (ls in cwd): ran without an approval prompt for a read-only command, answered in ~10 s, session auto-retitled.

## Traps (also in ops papercuts)
- The launcher picks --ozone-platform=wayland whenever WAYLAND_DISPLAY is set, ignoring DISPLAY: the first launch opened on the operator's seat. Launch with `env -u WAYLAND_DISPLAY -u WAYLAND_SOCKET XDG_SESSION_TYPE=x11 DISPLAY=:99`.
- Hermes runs ONE gateway per host; a sandboxed HERMES_HOME cannot boot its own backend while the host gateway runs (exits 0 'nothing to start' -> Desktop says 'Gateway inaccessible (runtime_exited)'). A pre-update gateway made this worse; `hermes gateway restart` first, then no sandbox.

## The shape worth aping (what the window should learn from)
1. Chat is the home surface, in the window's one column: user prompt as a bordered bubble; thought as a collapsed 'Thought >' line; tool activity as ONE collapsed summary line ('Explored config.yaml, ran 1 command', 'Ran ls + 1 command', elapsed) that expands to per-call rows, each expanding to the command + exit badge + output; final answer as plain prose; a timestamp + action strip (fork, copy, voice, retry) appears below the turn.
2. Composer: bordered single-line field that grows; leading '+' attach menu (Files/Folder/Images/Paste image/URL, prompt snippets, '@ to reference files'); trailing model pill (with favourites, grouped by provider, 'Run locally' offer), effort pill (Max/XHigh), mic, round send/voice button. Placeholder rotates ('Describe what you need', 'What's on your mind?', 'Push it further', 'Adjust or continue').
3. Left sidebar: Sessions/Bots tabs; verbs (New session, Capabilities, Messaging, Artifacts, Scheduled jobs) with keycap hints; search; PINNED and SESSIONS groups with month separators, relative age column, hover tooltip of the full title; profile rail at the bottom; status bar (Backend ready, workspace, Smart, version) with a right-click 'Show in status bar' menu.
4. Overlays, not pages: Settings (left nav tree + breadcrumb + Ctrl+K search, apply-button forms, toggles), Scheduled jobs, Profiles (SOUL.md editor) float as cards over a blurred shell and return to the previous route on close. Command palette (Ctrl+K) lists GO TO + PROJECTS.
5. Layout editor with an Interface-mode switch: Simple (sidebar + chat only: the lernie shape) vs Advanced (Review diffs, Files tree, Terminal rail in a right column). Everything flat: hairlines, no boxes-in-boxes, one accent blue, tabler/codicon glyphs, themed (Nous default; 12 palettes; light/dark/system).
6. Empty state: big serif wordmark + one-line tagline, nothing else.
