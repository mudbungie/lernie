## The gap bl-b98d and bl-15f0 leave

After bl-b98d a stop settles its own tool window, and after bl-15f0 the unpaired decline fires wherever the orphan sits. What remains is the crash itself: a driver killed mid-window (SIGKILL, OOM, power loss, a panic past commit_assistant) leaves an assistant tail whose tool_use has no committed tool_result and no hold mark. Every subsequent deposit starts a driver that returns Error::UnpairedToolUse — loudly now, but forever. The operator's only recovery is fork-from-history (ARCH §6 'the one non-replayable state'), which in an unattended fleet means the agent is dead. Frontends running dozens of sessions see this as 'the chat stopped working'.

## The reframe

§6's decline exists so the derivation stays total 'without forging results'. Settlement does not forge: bl-b98d's own shape — one in-band is_error tool_result per unanswered id — is exactly as truthful for a crash as for a stop; only the sentence differs ('the executor driving this window died before recording an outcome; whether the invocation ran is unknown; any side effects it performed stand'). And it moves the replay judgement to the only party with context to make it: the model, which reads in band that the window died and can re-issue the call or not. The decline instead hands that judgement to an absent human.

Safety is the lock: advance settles only under an acquired lease, and a live window's executor holds its lease for the window's whole life — kernel release on death is precisely the crash detector. A held branch never reaches the seam (the hold mark is adjudicated first, and a parked branch queues its mail).

## Shape of the fix

In advance::run, on the markless path, after the hold-mark check and BEFORE driver::deliver: read the transcript tail; if it is assistant-side with tool_use ids unmatched by committed tool_results, commit one is_error tool_result per unanswered id (the settle.rs shape, crash wording), then proceed — delivery lands behind a settled window, warrant reads ModelCallDue, the deposit revives the branch. Ordering is the point: pre-delivery, so the settlement composes wire-legal (§2.3 pairing is positional). The Unpaired warrant arm stays, now naming only the buried form — pre-fix debris — which remains the loud decline.

Amend ARCH §6 ('the one non-replayable state', hop step 3) and the §3.3 release-note that contrasts the mark with the decline. Gate: tests (idempotent re-entry; a crash-shaped fixture revives end-to-end; the held path untouched), docs, alignment.
