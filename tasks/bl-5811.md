Composed during the v0.4 fold review (bl-f739, main 2375d70). Deliverable: ARCHITECTURE.md amendments ruling each item. Blocks bl-507a — the classification module implements what this rules.

1. response.json fd lifecycle across attempts (LOAD-BEARING, §3.5/§4.4). During backoff between attempts, a closed file whose last segment carries Error reads as 'failed' though a retry is pending; a closed clean segment reads 'complete' while the step is still mid-retry. Recommended ruling: the harness holds the response.json fd open for the ENTIRE model call — all attempts and the backoff sleeps between them — closing only at step resolution, so fd-open stays the single in_flight signal (same observation as the /proc/<pid>/fd writer scan in §2.9 / lernie stop). Spec in §4.4 reading rules + §3.5.

2. §2.3 diagnostic-only contract vs sanctioned tail reads. §2.3 still asserts request.json/response.json have 'no runtime read integration anywhere in the harness', but §4.4 v0.4 openly lists readers (classification, await, harness retry) and v0.4-P3 + bl-c9ec shipped them. Recommended: amend §2.3 to a precise exemption — reads of event FRAMING (terminal line, Error/Finish kind, Usage) for state classification and metering are sanctioned; reads of CONTENT for context assembly remain forbidden (worktree invariant untouched).

3. Accounting across segments (§6 budgets, §8 metrics). Do failed attempts' Usage events count toward spend? Recommended: yes — every segment counts (failed attempts cost real money); the last-segment-authoritative rule governs context, never accounting. Also rule whether max_wall_seconds includes backoff sleeps (recommended: yes — wall is wall).

4. FinishReason::Pause (provider resumable pause, e.g. Anthropic pause_turn). Neither complete nor failed; the wire expects the partial assistant message replayed back with a continuation request. Rule how a step absorbs it (continuation invocation within the same step vs a new step whose read state includes the partial). Check brazen's Pause round-trip shape (FinishReason::Pause, request-side Content replay) before ruling — do not invent semantics the wire contradicts.

5. Finish{Refusal} (HTTP 200, exit 0). Terminal for the model call; rule the workflow reaction: root conversation surfaces it as the terminal response; a subagent's refusal reaches the parent through the normal await/compaction path — likely one sentence in §6 events plus a workflow-event name.

6. Cross-machine portability of brazen row names (§4.1). A conv-repo replayed on another machine needs same-named rows in that machine's brazen config — same contract as v0.3's provider names, but state it explicitly in §4.1 so it is a documented expectation, not an accident.
