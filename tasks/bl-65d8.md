Deliverable: edits to `docs/ARCHITECTURE.md` and `docs/TAXONOMY.md`. Living document — this body records the decision; the docs are the artifact.

## The defect

`docs/ARCHITECTURE.md:166` (§2.3 step 4) gives Completion **three** arms: *"A terminal event: final response, stop (§2.9), budget exhaustion (§6)."*

Step 5 (`:167`) fires on only one of them, because `:330` (§2.9) says: *"A stopped agent deposits no result: a stopped childs parent derives `{status: stopped}` through `check`/`await` (§2.5)."*

So `await` is not a waiting primitive. It is a **fallback for the two terminal arms that skip step 5** — §2.5 (`:252`) says so outright: `{status: stopped}` / `{status: budget_exhausted}` are *"the fallback for children that die without returning."* That is a special case, and the reframe is to delete it.

## The fix: make step 5 total

**Every terminal event deposits a result message.** Final response, stop, budget exhaustion, hard crash. Then the inbox is the only return path, revival-on-deposit (§2.11) wakes the parent in every case, and `await`/`check` have nothing left to observe.

The parent never blocks. It dispatches, terminates its step, goes quiescent, and is revived by the deposit. **Waiting on a child is the same act as waiting on the user** — the bidirectional completion of §2.5s *"From the childs perspective, its parent is indistinguishable from a user."*

## No watcher is needed

§2.11 (`:373`) forbids one: *"No abandonment, no takeover, no watcher left behind."* It is not needed. Decomposing the arms:

| Terminal arm | Catchable | Who deposits |
|---|---|---|
| Final response | — | Executor, step 5 (already specced) |
| Stop (user/cascade/timeout) | SIGTERM — yes | Executor, in the handler |
| Budget exhaustion | Harness-issued — voluntary | Executor, before exit |
| SIGKILL / OOM / panic | No | The §8 sweep |

Three of four arms need no observer — just "deposit on your way out." Only hard crash needs one, and §8 (`:812`) **already enumerates exactly the right candidate set** for the silent-death metric: branches with no live executor that *"either died mid-work … or, for a child, never deposited a result message."* Today it counts them. Make it deposit for them. Same query, one more action, zero new mechanism.

Sender on a swept deposit is the **child**, not the harness — the parents inbox is sender-namespaced and the "a message from the child exists" derivation depends on it. The sweep is the scribe, not the author.

## Epitaph — the union, not the exceptions

A result message always carries: the **terminal ref** (pinned, §2.6), the **manner of ending**, and the **terminal response** *if the agent spoke*. A clean return is an epitaph with a terminal response; a stop is an epitaph without one. One message, one delivery path, one work-product transfer, **no branch anywhere**. Defining epitaph negatively ("terminal state without a terminal response") re-imports the special case through the vocabulary door.

## Scope

- `docs/ARCHITECTURE.md` §2.3 step 5 — becomes total (every terminal event deposits).
- `docs/ARCHITECTURE.md` §2.9:330 — inverts: a stopped agent deposits an epitaph.
- `docs/ARCHITECTURE.md` §2.5 — the `await` / `check` paragraphs delete. Model-facing verbs reduce to `dispatch` and `message`.
- `docs/ARCHITECTURE.md` §8:812 — the silent-death sweep gains the deposit action.
- `docs/TAXONOMY.md` — entry for **epitaph**.

## Explicitly out of scope

- **Code deletion** (`src/prompt/tool/builtin/await_tool/`, `src/prompt/merge/`) — separate balls, this is the doc.
- **Fan-out join.** Each deposit wakes the parent separately, costing ~2 extra model calls on a 3-way fan-out. Accepted: it is what lets the parent react to child 1 before child 3 lands, and §2.5 already concedes blocking awaits flaw (*"a parent parked in a blocking `await(handle)` has no step boundary until that await resolves"*). If it ever bites, the join is a §6 workflow binding — config, not schema.

## Trap for the implementer

Do **not** synthesize a `message` tool call to perform the return. It would put a `tool_use` block in `messages/NNN-assistant.json` that the model never emitted, breaking §2.3s *"exactly as the steps authoritative attempt segment emitted them"* (`:185`) and un-terminating the step (`:166`). The deposit is executor-side, outside the transcript. `message` stays the tool an agent calls when it *chooses* to send; return is not a choice, so it is not a call.
