Producer half of bl-9e96. §3.3 mandates that at conversation-repo creation the harness commits, onto the initial `main`: (a) every available tool's JSON schema (from <harness-root>/tools/<name>.json) under descriptions/tools/<name>.json, and (b) every available skill's SKILL.md frontmatter (name+description) under descriptions/skills/<name>.md. Inherited by every branch via git; composed into context on every model call. bl-9e96 built the CONSUMER (src/prompt/dispatch/tools.rs::compose intersects declared role tools against descriptions/tools/*.json); with no producer that tree is empty, so compose yields [] in production (named in §3.3 shipped-state note; tools.rs:16/:25).

Design points (see §3.3 amendment, docs-gate ball): ONE mechanism over TWO artifact kinds (tools schemas + skill frontmatter), not two producers. No SSOT violation — <harness-root>/{tools,skills}/ is SSOT for 'what this install provides'; the conv-repo descriptions/** snapshot is SSOT for 'what this conversation is pinned to see' (same rationale as copy-not-symlink §3.3 and providers.yaml frozen-at-creation §2.2). HOME is the conversation-repo creation routine (initial main commit) — which itself is not yet built in production (only src/template/mod.rs writes goal/soul; no orphan-main scaffolding). So build the producer AS the descriptions-always step of that creation routine, not as a bolt-on.

Deliverable: creation routine writes descriptions/tools/*.json and descriptions/skills/*.md onto initial main from the harness-root pools. Closes the second half of the shipped-state note too — the tool-entry description (SKILL.md frontmatter, currently None in compose) gets populated by the same pass. 100% coverage, <=300-line files.
