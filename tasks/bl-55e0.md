## Repro

```
$ lernie new /tmp/ws2 && EDITOR=true lernie config /tmp/ws2 x --from nosuch
lernie config: config authoring git: git ["worktree", "add", "-b", "config/x", "/tmp/ws2/.config-author", "config/nosuch"] exited with exit status: 128: fatal: invalid reference: config/nosuch
$ echo $?
1
```

Reproduced on the crates.io 0.0.1 binary and on a `make install` build of
`main` (`6a4a47d`).

## Why it is a papercut, not just noise

It leaks three internals a user has no business seeing and cannot act on: the
plumbing argv as a Rust `Debug` array, the transient authoring checkout path
`.config-author` (README: *"The transient checkout is torn down on every exit
path"* — i.e. deliberately invisible), and the `config/` ref-namespace prefix
the CLI otherwise hides (`--from` takes a bare `<source>` name, per
`lernie config --help`: *"Fork a new branch off `config/<source>`"*).

It is also the only decline in the verb set that reads this way. The same
product's missing-recipient message is the standard to match:

```
lernie message: no agent "ghost" in this workspace — a message is addressed to an existing agent (ARCH §2.11); check the id against the workspace's `agents/*` refs, or start an agent with `lernie prompt` / `lernie dispatch`
```

`docs/USER_STORIES.md` US-05 enumerates the `--from` acceptance
(*"`--from <src>`: a new `config/<name>` exists and `git merge-base
config/<name> config/<src>` **succeeds**"*) but names no decline for a `<src>`
that does not exist, so this path was never given a voice.

## One-line fix

Resolve `config/<source>` before the `git worktree add`, exactly as the agent
verbs resolve `agents/<id>` first, and decline with the lineages that do
exist:

```
lernie config: no config lineage "nosuch" in this workspace — existing lineages: default, strict, lone
```

## Everything else in this verb walked clean

For the record, the same pass verified through the real binary: the no-op
decline (`EDITOR=true` → `config/default unchanged: the edit changed nothing,
so no config commit was authored`, exit 0), a real advance, `--from`
(merge-base succeeds), `--orphan` (merge-base fails), the `--from`+`--orphan`
exclusion (`pass --from <source> or --orphan, not both`, exit 1), a failing
editor (`edit step: editor exited with exit status: 1`), and the transient
checkout torn down on every one of those exits. Two of those — the empty-commit
decline and the `--from`/`--orphan` exclusion — US-05 lists as unit-only; they
now have a hands-on observation through the shipped binary.

## Severity

Papercut. Correct refusal, correct exit code, nothing written; only the voice
is wrong.

Filed by an outside evaluation pass (wharfinger) walking 0.0.1 from the public
docs only; not claimed, not fixed.
