Found while landing bl-b415 (the ARCH §5.1 correction: the manifest is the inclusion list, not a sequencing/budget file).

**The gap.** `src/prompt/compactor/mod.rs::compactor_goal` hands every compactor this boilerplate:

> "Read the branch's transcript, prior summaries under `summary/`, and work products, and produce a signal-preserving, minimal view … Use `mark_for_deletion` to nominate superseded files — stale transcript entries under `messages/`, a prior `summary/` you are replacing, spent `skills/` bodies."

Two of the three named sources are unreachable to it:

1. **Not composed.** `template/manifest.yaml` gives the compactor `pinned: [goal.md, soul.md]`, `order: []`. `goal.md`/`soul.md` ride the system slot, so its body is empty and its context is system slot + transcript tail. The dispatching branch's `summary/**`, `skills/**` and work products are in the inherited worktree and compose **nowhere** (ARCH §5.1 as corrected by bl-b415).
2. **Not readable.** The compactor's `tools:` grant is empty by design (§2.7 deletion-only; `template/providers.yaml`, pinned by `src/install/tests.rs`), and its injected pair is `write_summary` + `mark_for_deletion`. There is no `read_file` and no `bash`, so unlike a worker it cannot reach an uncomposed file at all.

So a compactor asked to replace `summary/003.md` has never seen `summary/003.md`, and a compactor asked to nominate spent `skills/` bodies cannot enumerate them. Only the transcript is genuinely in view.

**Not fixed in bl-b415**, which was docs-only by ruling. ARCH §2.7 and §5.2 now *state* the gap honestly and point here.

**Options, to be attacked before choosing:**
1. Add `order: [summary/**]` (and possibly `skills/**`, work products) to the shipped `compactor` entry in `template/manifest.yaml`. Config, severable, no code — but it spends the compactor's 50k budget on material it may not need, and work products have no clean glob (they are "everything else").
2. Decide the compactor genuinely only needs the transcript, and **fix the goal prose** to stop naming what it cannot see — cheapest, and arguably honest: the summary it writes supersedes the prior one by position, and `mark_for_deletion` on `messages/**` is what the transcript already names.
3. Give the compactor a read tool. Weakens the deletion-only structural guarantee's simplicity (a read tool is not a write, so the guarantee survives) but adds a grant to a role whose empty grant is load-bearing in the docs.

Whichever way it goes, the goal prose in `compactor_goal` and the shipped manifest entry must end up agreeing, and ARCH §2.7 / §5.2 must lose the "tracked as its own ball" pointer.
