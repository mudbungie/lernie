yog bl-9043 (yog main a3e0fdf4, edition 20, yog REMOTE §8.4) added two optional fields to the §8.4 enrolled reply: rendezvous_pub and pairing_salt, hex, present together or not at all (a loopback-only engine sends neither; one without the other is malformed). The phone reads its roving material (REMOTE §13.3) from exactly this envelope.

src/reply/enrolled.rs decodes a fixed field set and Enrolled::envelope re-encodes only the six (grade, name, address, ca, cert, key), so the symbol this seat draws for a phone carries no rendezvous material and the phone can never rove. src/seat/enroll/entry.rs (--into) writes the four entry files and not the two rendezvous files lernie's own src/channel/rendezvous.rs reads (rendezvous.pub, pairing.salt).

Fix: Enrolled carries an Option pair; decode reads both, refuses exactly one; envelope() writes them when present (key order stays serde_json's sorted order, matching the engine encoder); --into writes rendezvous.pub and pairing.salt beside the entry when present, under the same names and modes the engine mints. caption() stays material-free. Tests: decode + re-encode against yog's corpus fixture corpus/reply/enrolled.json byte-for-byte (present) and a loopback fixture (absent); half a pair refused; --into writes six files vs four. Note the payload grows to ~1729 bytes and no longer fits QR level Q (still M) — check the symbol renderer's level. Amend DESIGN where the envelope's six fields are stated.
