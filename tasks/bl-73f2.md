Follow-up to bl-7b83: timing bets that remain after it, measured by running the suites in a loop under CPU load locally (48 spinning processes, the test binary at nice 15, 30 sequential runs).

Fixed in bl-7b83, for reference: the DHT walk's deadlines now read `Dht.clock` (system clock in production), and `src/dht/tests/steered.rs` is a transport whose fake-node silence comes from the fake's own mood (`fake::ignores`), so a deadline under test moves only past declared silence. frontier.rs and window.rs use it. The offframe 20 s bets became a shared hung-not-slow `HUNG`; ladder held/recall sleeps became `ended(&b)`, which polls the held line's verdict; the v6 loopback punch window is long only where a v6 listener stands.

Remaining, by how often each failed in that loop:

1. `channel::ladder::tests::held::a_line_the_engine_ended_re_enters_the_ladder_however_it_ended`, Garbage fate, FIRST ask: 8 of 30. `test_support/roving.rs` Fate::Garbage and Fate::Reset sleep 100 ms "for the answer to be taken" before corrupting or resetting the line. Under load the seat has not read the answer yet, so the first ask fails ("received corrupt message"). Fix: gate the fate on a signal the test sends after the first ask returns, not on a sleep.
2. The remaining DHT tests (`dht/tests/{bootstrap,items,walks,observed}.rs`) still use `client()` with quick()'s 300 ms system-clock deadline, so every live fake must answer within 300 ms. bootstrap::the_topology_walk_never_answers_the_bootstrap and items::get_reads_the_newest_verified_item_and_ignores_a_forged_one each failed 1 of 30. Fix: move them to `steered(...)`, which is mechanical.
3. Ladder Bench (`channel/ladder/tests.rs`) walks the DHT on the system clock with a 2 s deadline, and punches with real windows (direct 300 ms, window 3 s; 300 to 500 ms in the recall/said/refusals expiry tests). recall::a_call_that_expires_leaves_no_cache_so_the_next_climb_reads_presence failed 1 of 30: presence was not read. A punch also once handshook with the wrong peer ("got ClientHello when expecting ServerHello"), which looks like a simultaneous open crossing two concurrent tests on loopback. Fix: let a Bench steer the DHT clock (the field exists), and make the punch window under test test-controlled.
4. `channel::ladder::tests::held::pings_are_discarded...` still has `sleep(200ms)` so the pings reach the socket before the next ask. No state shows that today.
5. Lower-bound waits that are safe and left as they are: punch tests `elapsed() >= 400ms`, seat follow `elapsed() >= SETTLE`.
6. Reported by the coordinator from builder runs, not reproduced here: a coverage-tool segfault once. Separately, bl-11da measured that under the llvm engine the two bl-7b83 tests did not fail: ptrace slowdown is part of why these bets lose.
