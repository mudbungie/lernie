## What 18 is, shape by shape

- **`reply/follow`'s tool-window entry gained `held`** (yog bl-58bb) — the
  capability control's reason for parking the call, beside the `tool_use` id
  and the tool name. A held invocation is parked *before* the executor is
  entered, so neither `input.json` nor `output.json` lands and the window said
  nothing: the one lane an operator has open while a command they did not
  expect is about to run reported the conversation at rest and ended the
  stream. Presence is the status, `exit_code`'s own discipline on the same
  entry. The RENDER half of this is bl-3a1f and lands beside it.
- **`reply/steps` rows gained a fourth `framing` word, `in_flight`** (yog
  bl-ab53) — the step being written right now, told apart from the one an
  interrupt cut. A new VALUE and not a new key, so no field signature can see
  it; this seat carries class tokens verbatim on §4.9's rung 3, and what it
  owes is the assertion that it does.
- **Two new ops and one new reply kind, at no version cost** (yog bl-dd88,
  REMOTE §9.22): `request/proposals`, `request/proposal` and
  `reply/proposals` — the learning loop's operator half. A reviewer stages a
  config patch on `proposal/<reviewer-id>` and the whole loop turns on a person
  reading it and vetoing it; nothing on this wire could, so the veto lived at
  `litany proposal` on the engine's own box. Both ops are `surface: control`,
  so both owe this seat a control or a cited line in `parity.toml`.
- **`reply/ops` rows' `client`** is already decoded and painted on both faces
  (bl-183b, PROTOCOL 16) — recorded here so the next reader does not go looking.
