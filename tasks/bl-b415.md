Found by bl-af3f (the alignment gate of bl-c8ed), and the finding is older than that ball.

§5.1 states the invariant absolutely: "**Everything inside a branch's worktree is composed into that agent's prompt.** … There is no exclusion list, no filter, no 'this path is for the harness only.' … The invariant is what lets the manifest be a *sequencing and budget* file rather than an *inclusion* file — the question the manifest answers is 'in what order and under what budget,' not 'which things.'"

The shipped assembler does not do that. §5.2's own shipped-state note concedes it in passing: composition is the manifest's `pinned` paths, its `order` categories, and the transcript tail — and "**A role absent from the manifest's `roles:` map** assembles transcript-only." So the manifest *is* the inclusion filter, and a worktree file named by neither list composes into nothing. Under the shipped `worker` manifest (pinned: goal.md, soul.md, descriptions/**; order: summary/**, skills/**) that set is non-empty and ordinary: every work product the agent writes — a `feature.txt`, a note, and now `name` (§2.3, bl-c8ed) — is in the worktree and out of the prompt.

Practical impact is muted (an agent reaches its own files with `read_file`), which is why this survived; the cost is that §5.1 is quoted as load-bearing by §2.2, §5.2 and PRINCIPLES 'Context has one home', and an implementer who trusts it reasons wrongly about what a fork sees.

Pick one and make the docs and the code agree:
1. **The manifest is inclusion** — amend §5.1 to say so, delete the 'sequencing and budget, not inclusion' claim, and re-check every section that leans on it (§2.2 control-files-leave argument, §5.2, PRINCIPLES). Cheapest, and matches shipped behaviour.
2. **The invariant is real** — assembly composes every worktree path, with the manifest ordering and budgeting what is already in. Bigger, and needs an answer for paths a role should not pay tokens for.

Not urgent and not a bug report against any one ball; it is a spec/implementation divergence to settle deliberately. Related: lernie bl-d55f (surfacing the agent name into assembled context) is an instance of the question — under reading 1 it adds a `pinned` entry, under reading 2 it needs nothing.
