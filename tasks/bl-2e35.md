Append one new job, `prune-release-branches`, to `.github/workflows/release-plz.yml`, after the last existing job (`release-binaries`). Change nothing else.

WHY: release-plz pushes a new timestamped `release-plz-*` branch every time it refreshes the release PR, and it pushes the branch BEFORE opening the PR. Across the sibling repos this piled up badly — brazen accumulated 25 such branches against a single ever-created PR, because PR creation was 403ing and every push to main stranded another branch. lernie has none yet only because it had no release automation until now; the same accumulation would start with its first push to main.

"Automatically delete head branches" has been enabled on the repo, but that only fires on MERGE — it does nothing for closed-as-superseded or orphaned branches. This job closes that gap: it runs right after the release-PR job (`needs: release-plz-pr`), so the branch backing the current release PR is already open, and "has no open PR" is an exact test for "superseded or orphaned". No allowlist, no age heuristic, no stored state — the open-PR set is the single source of truth.

VERIFY: `python3 -c "import yaml;print(list(yaml.safe_load(open('.github/workflows/release-plz.yml'))['jobs']))"` prints `['release-plz-pr', 'release-plz-release', 'release-binaries', 'prune-release-branches']`.
GATE: `make ci` passes.
