`delete-workspace` is the one op bl-4a2c looked at and refused to build, and
the reason is that there is nothing here to build it out of.

**This seat has no destructive act at all.** Every control it has adds or
changes something and is undone by doing the other thing: aiming, selecting,
depositing, nudging, starting, enrolling, and the four tuning gestures. None
of them destroys a thing, so there is no arming idiom, no confirmation shape,
no wording convention and no test scaffolding for one — and the first
destructive control must not invent all five in the same commit that also
happens to unmake a workspace.

The wire already states the arming: the envelope carries `typed`, and yog
refuses the act unless the workspace is its own, nothing in it is live, and
the typed name matches exactly. So the seat's half is a text box whose
contents must equal the wall's name before the control is live — which is a
real interaction with real states (empty, mismatched, matched, in flight,
refused) and belongs in a ball that is about the idiom rather than about the
op.

What lands with it is the convention every later destructive control follows,
so the second one is config and not code.

`reply/deleted` is `{kind, ok}`; this seat decodes no such kind yet.

The exemption row in `parity.toml` cites this ball until the idiom lands.
