src/prompt/dispatch/transfer.rs CONTEXT_EXCLUDES = goal.md, soul.md, messages, summary, skills — but not descriptions, which ARCH §2.2 counts as inherited config context, not a work product. A dispatched child's dispatch commit prunes descriptions/** to the child role's grant (§3.3); when the child returns, the fork-point→terminal transfer diff carries those deletions into the parent as if they were work. Observed in the fleet e2e (/tmp/claude-1000/-home-mark-dev-lernie/d8b3c251-6d27-458f-a55c-166907ca93db/scratchpad/fleet-e2e/run-20260730-171212-2064167): coordinator's request tools went 7→3 after its children returned; git log --name-status on the root branch shows 'work-product transfer [<sensor-id>]' deleting descriptions/{tools,skills}/{bash,dispatch,read_file,slack_post,load_skill}. Knock-on: the next child's return patch no longer applies → declined at refs/lernie/conflicted/<child-id>. A long-lived parent is silently disarmed by its own children. Fix: add ':(exclude)descriptions' to CONTEXT_EXCLUDES (the §2.6 transfer is defined as filtered to work products; descriptions is context by §2.2) + a test reproducing parent-toolset survival across a child return. Check whether the conflicted-ref decline path needs a companion test.
