`compactor::checkpoint::origin` derives the branch's **checkpoint origin** — where the compaction clock measures from — with three OR'd `--grep` patterns and `git log -n 1` (newest-first) from `HEAD`. The founding pattern is:

```rust
let founding = format!(r"\[{agent_id}\]$");
```

(`src/prompt/compactor/checkpoint.rs`, `origin`.)

That is meant to match the branch's **dispatch commit**, whose subject is `dispatch: <role> [<id>]` for a child and `step 001: dispatch [<id>]` for a root (§2.3, §2.7). The module doc says so: *"Both end in `[<agent-id>]`, so one anchored pattern founds every branch and the root is not a special case."*

## The defect

The executor's own **transcript commits end in the same tail**:

```rust
// src/prompt/dispatch/transcript.rs:209
let msg = format!("transcript {seq:0w$}: {origin} [{conv_id}]", w = SEQ_WIDTH);
```

`conv_id` is the agent's own id. So does the stray-recovery commit (`drain.rs:226`, `transcript: recover delivered stray [{conv_id}]`).

`git log -n 1` walks newest-first and stops at the first match, so `origin` returns the **newest transcript commit**, not the founding one. Consequences, all from the one read:

- `commits_since_checkpoint` counts commits after the newest transcript commit — effectively 0 or 1 forever. `every_n_commits` **never** reaches its threshold, so configured intermediate compaction never fires.
- `seconds_since_checkpoint` measures from that same commit's committer time, so `every_t_seconds` is equally dead.
- The compaction span's lower bound (`land/span.rs`, `checkpoint::origin` read from `P`) is likewise mis-derived when no compaction base exists yet.

## Why the suite is green

`src/prompt/compactor/checkpoint/tests.rs` builds branches with synthetic subjects (`"root"`, `"step"`, `"step after"`) that carry no `[<agent-id>]` tail at all, so the founding pattern matches nothing and the fallback (`root_of`) answers. The production subject shape is never exercised against `origin`.

## The fix, and its precedent

bl-22a5 hit the same question for the retarget landing and answered it in `role::founding_sha`: match the two dispatch subjects **exactly** rather than by the tail alone —

```rust
let pattern = format!("^(dispatch: .+|step 001: dispatch) \\[{agent_id}\\]$");
```

`origin` should read the same fact the same way. Single source of truth argues for one derivation rather than two patterns that must stay in step: `origin` is "newest of {founding, compaction base, retired merge}", so it can OR `founding_sha`'s pattern with its two landing prefixes, or call `founding_sha` and compare.

## Coverage

The regression pin is a checkpoint test whose branch carries **real** subjects — a `step 001: dispatch [p1]` founding commit plus two `transcript NNN: <origin> [p1]` commits — asserting `commits_since_checkpoint == 2`, not 0.
