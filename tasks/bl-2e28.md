Deferred from bl-8801 (packaging hygiene). The evaluation runner `crates/agent-eval` (ARCH §9.3) was complete and fully covered, but its agent seam dangled at BOTH ends: no harness driver shipped (END 1), and `LERNIE_EXPERIMENT` was a hand-off nothing applied (END 2). This ball shipped the driver and closed both ends.

DECISION — in-repo workspace crate, not a script (Astrolabe). `crates/lernie-eval-agent`, `publish = false`, one external binary `lernie-eval-agent`, installed by `make install` (PATH_BINARIES). Reasoning: an integration is an external binary (PRINCIPLES "Integrations are external binaries"), so it must NOT be a `lernie` verb — and "if it can't be tested, it mustn't be built" rules out a scripts/ shell script, which would sit outside the 100%-coverage gate. A crate rides the workspace gate (fmt, clippy, tarpaulin 100%, 300-line cap) and is exercised against a stub `lernie` (`crates/lernie-eval-agent/tests/driver.rs`), the same no-live-traffic discipline as the runner. The driver drives the harness exclusively through the front door: it execs `lernie` from PATH (`new` → `config` → `prompt`); no linked binding (tool subprocesses need an exec'able `lernie` anyway, so linking buys nothing).

Per run the driver: (1) seeds the run's isolated LERNIE_HOME from the machine's lernie config root ($XDG_CONFIG_HOME/lernie else ~/.config/lernie; deliberately ignoring LERNIE_HOME, which names the per-run home) — `models.yaml` + the `template/` config-root override, seed-if-absent; the wire is machine-local by design (ARCH §4.2/§9.2) and these are the two existing front doors, so no new flag or env var exists; (2) `lernie new`; (3) APPLIES the experiment (END 2): `lernie config <ws>` with EDITOR='cp -f "$LERNIE_EXPERIMENT"' — the experiment lands as an ordinary config commit, the only place the harness reads workflow policy from (§2.2); baseline's empty diff declines cleanly; (4) `lernie prompt` with the task prompt grounded in the shared cwd (the agent's shell starts in its worktree, so the driver names the workdir and instructs `cd`); (5) writes LERNIE_EVAL_REPORT (workspace, agent id). Exit code per contract: ignored. `--agent` stays REQUIRED with no default — which driver runs the agent under test is an experiment-defining input; a hidden default would silently bind every measurement to it.

Runner fix riding along: `experiment::resolve` now canonicalizes the workflow path — LERNIE_EXPERIMENT rode to the driver relative to the RUNNER's cwd and named nothing from the driver's per-run cwd.

SEAM BUG FOUND AND FIXED (first non-anthropic live wire): lernie's assembler framed tool results as Role::User carrying ToolResult blocks (anthropic dialect shape). brazen's canonical shape is Role::Tool — the anthropic protocol folds Tool→"user" (wire-identical to before), while ollama_chat/openai/openai_responses REJECT user-slot ToolResult ("user accepts only text content") and need Role::Tool to fan out role:"tool" messages. Every prior live call had been anthropic-protocol or toolless, so this never surfaced. Fixed in `assembler.rs` (tool origin → Side::Tool → Role::Tool) + `advance.rs` warrant (User|Tool tail ⇒ ModelCallDue); ARCH §2.3/§2.5 prose amended. Without this no non-anthropic wire can run a tool loop at all.

Shipped alongside: `experiments/single-attempt/` (retry.max_attempts: 1) — the smallest non-empty config diff, the reproducible subject for the applied-experiment proof (baseline cannot demonstrate application: its diff is empty).

LIVE EVIDENCE (this machine, no anthropic credential; local ollama via bz provider row `local`, model bz-smoke:latest 630M): hand-run of the driver under the runner contract with CONFIG=single-attempt — driver exit 0, report file written (workspace + agent id), `git show config/default:workflow.yaml` in the run workspace byte-identical to experiments/single-attempt/workflow.yaml (diff clean), and the model emitted a native bash tool_use (`cd <workdir> && ls -l`) that crossed the ollama wire and came back (steps 001+002) — the experiment demonstrably in force and the grounding honored.
