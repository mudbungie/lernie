Systemic hazard seen during parallel development: the gate's e2e tests exec whatever bz is on PATH (~/.cargo/bin/bz, machine-global mutable state); any agent's gate running while another installs a different brazen version gets five spurious version-guard failures. Single-source fix candidates (pick after reading how e2e tests locate bz and what §4.4 specifies): have the test harness install/cache the pinned bz into target/ (keyed on the Cargo.toml pin) and put that dir first on PATH for spawned executors, so a worktree's tests always run the worktree's pin. Keep the runtime resolution (PATH) unchanged for real use — this is test determinism, not a product change. Docs: contributor section note.
