## Proven, against real workspaces

A conversation whose `messages/` begins at `002-*` and has no `001-*` at all.
The branch log shows a `compaction base` commit sitting directly on `step 001:
dispatch`. `git show --stat` on that base re-adds `messages/002…020` **and
`summary/001.md`, and nothing named `001-user.md`.** The compactor child's own
transcript records the call verbatim: `mark_for_deletion` with input
`{"path":"messages/001-user.md"}`, and the tool returns `{"status":"marked"}`.
`mark_for_deletion` is a literal `git rm` (`src/prompt/compactor/tools.rs`), and
`land/base.rs` squashes the deletion into the new base.

**Correlation is total, with no counterexample:** across every agent directory
in two workspaces, the directories missing `001-*` are exactly the directories
that have a `summary/`. Every non-compacted conversation still has its
`001-user.md`. Missing-001 ⟺ compacted.

## Why the FIRST message and no other — the actual root cause

**The opening prompt is written to disk TWICE, and the compactor is shown one
copy while it deletes the other.**

`prompt/dispatch/mod.rs` deposits the user's message to the inbox, which drains
to `messages/001-user.md`; the same text is also written as `goal.md` by
`write_dispatch_files`. Then the compactor's own goal quotes the dispatching
branch's `goal.md` **inline** (`src/prompt/compactor/mod.rs`):

    Use `mark_for_deletion` to nominate superseded files — stale transcript
    entries under `messages/`, …
    <dispatching-branch-goal>
    {parent_goal}
    </dispatching-branch-goal>

So the opening prompt is the one transcript entry that reads as **pure
duplication** to a model told to nominate superseded files — it is looking
straight at a second copy of it. Every later user message has no duplicate and
survives. The compactor is not malfunctioning; it is correctly identifying
redundancy and resolving it by deleting the copy the operator reads.

## The fix this points at

The duplication is the defect, and it is the house rule verbatim: "Every fact
has one authoritative home and everything else derives from it; two
representations of one fact will drift." `goal.md` and `messages/001-user.md`
are two representations of one fact.

Prefer **dissolving the duplication** over exempting a path:

- If `goal.md` can derive from the first inbox deposit rather than being written
  beside it, the compactor never sees two copies and the special case evaporates
  — the missing-reframe resolution, not a branch on "first".
- If it genuinely cannot, then the compaction **span** should begin after the
  dispatch entry rather than at the branch base. That is one change to where the
  span is cut, and still not an exemption.
- A `keep_first` knob mirroring `keep_recent` is the LAST resort: it is policy
  added to work around a duplication nobody wants, and it leaves the two copies
  in place to drift.

Whichever holds, the acceptance test is behavioural and must be written from the
operator's sentence: **run a conversation past a compaction and assert
`messages/001-*` is still there and still renders.**
