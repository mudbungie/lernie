## Resolved — declaration closure + a callable guard (not a compactor special case)

The wire request has two independent facts about tools, and the code had
only one of them:

- **What the request declares** is a property of the *request as a whole*.
  A provider validates it that way: a `tool_use`/`tool_result` pair naming
  a tool the `tools: [...]` array omits is refused outright (the repro:
  codex/`openai_responses`, `parse_input` "tool accepts only text
  content").
- **What the caller may call** is a property of the *role*. For the
  compactor that is exactly `write_summary` / `mark_for_deletion`, and
  §2.7's deletion-only guarantee is structural only while that holds.

## Deviation from the architect's leaning (recorded per instruction)

Tumult's leaning was the compactor's request declaring "its own two tools
plus every tool named in the inherited transcript". Implemented — but
**not as a compactor rule**. The code proves it is the general one: any
request whose history names a tool its `tools:` array omits is refused,
and that is reachable for an ordinary worker too (a model hallucinating a
tool name still lands a `tool_use`/`tool_result` pair in the transcript by
§2.5 pairing, wedging every subsequent step on that branch). A compactor
special case would have been a missing reframe. So the closure is a rule
of the composer, applied on both step drivers, and the compactor needed no
declaration code of its own — only the guard.

## The seam

`src/prompt/dispatch/tools.rs::compose(worktree, role, declared, history)`
is now the single home for "what does this request declare?", summing
three answers in order:

1. **Election** — declared names ∩ committed `descriptions/tools/*.json`
   (unchanged; a declared name with no schema is still dropped).
2. **Injection** — `compactor::builtin_tool_schemas()` for the compactor
   role alone (moved here from `advance/hop.rs`, so `run_exchange` and the
   hop now agree — previously only the hop injected).
3. **Closure** — an entry for every tool the assembled history names that
   the array does not already carry. Committed schema sent verbatim where
   present; a bare `{"type":"object"}` stands in where absent (a name the
   model invented, whose exchange landed anyway). Reads the opposite way
   from election on purpose: a name the history references is never
   dropped, because the exchange has already happened.

Transcript fidelity is preserved — the declaration is widened to fit the
history, never the history rewritten to fit the toolset (§2.3 entries are
immutable, §3.3 framing is transcript-backed).

**The guard** (nothing prevented execution before — `SpawnTool` resolves
purely by name): `compactor::refusal(role, tool)` returns the decline text
for a compactor reaching for anything but its two, and
`dispatch/tool_step.rs` consults it *before* the executor. The result is an
ordinary `is_error` `tool_result` the model reads and steps on; the
executor is never entered. `Resolved` gained `role` (borrowed from
`WorkerConfig::role`, its one home) so both drivers can pass it.

  tools; (c) the plain no-tools worker hop still declares nothing.

  incl. no duplicate when a compactor's own history names `write_summary`.
- `src/prompt/compactor/mod.rs` — `refusal` is `None` for the two tools and
  for every non-compactor role.
