## SETTLED (delivered as tracked doc edits — docs/TAXONOMY.md §1 'Role' + docs/ARCHITECTURE.md §4.3 'Roles')

**Definition (authoritative home: TAXONOMY §1, following the repo's lernie's-stance convention; §4.3 is the mechanism).** A role is a pure config-selection key: the name under which a config commit bundles what a dispatch needs. It carries no behavior and is not an identity. The entry states what a role does NOT solve (behavior hook, permission/identity, persona, wire message role, workflow position).

**Correction to this ball's premise:** a role binds FIVE things, not four — the body missed the context-assembly policy (manifest.yaml is role-keyed, §5.2, src/config/manifest.rs). Bindings and single homes: model (providers.yaml roles.<name>, cross-validated vs models.yaml), toolset (tools: list), soul (souls/<name>.md — name is the path), assembly policy (manifest.yaml roles.<name>), grant v1.1 (grant: block).

**Open set.** Valid iff the governing config commit lists roles.<name> AND carries souls/<name>.md (exactly what the dispatch tool's validate_role checks). Harness never enumerates role names; verifier-with-zero-code holds.

**Noun vs adjective:** selection key (adjective side) — confirmed. An agent's role has ONE runtime home: the dispatch commit subject (src/prompt/role.rs); roots default to worker, so a config that starts roots must define worker.

**Compactor wrinkle VERIFIED then dissolved.** Verified: write_summary/mark_for_deletion are injected in advance/hop.rs for role==compactor alone, never a tools: list, never in descriptions/**. Resolution: 'primitive role vs config role' is dissolved, not adopted — the pair is the compaction MERGE procedure's instrument (deletion-only is structural only because it is not config); the compactor role itself is ordinary config (model, soul, manifest entry). The three names code keys (worker/compactor/verifier) are the closed workflow vocabulary (§6 severability line: interpreter vocabulary is code, bindings are config) — one kind of role.

**Dispatch relationship.** Any defined role is dispatchable by any dispatcher; child role unconstrained by parent's.
