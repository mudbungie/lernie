## Scope
User decision 2026-07-12: lernie is strictly substrate, but it ships minimally operable — a TUI wrapper is in scope. A terminal frontend obeying the §3.5 contract exactly: filesystem reads + lernie CLI invocations, nothing else; no persistent state; restart = re-read.

## Minimal-operability feature set (proposed)
- Agent tree view: branches, agent-state markers (live / in_flight / quiescent / stopped, §3.5 classification) plus declined-transfer and budget-exhausted ref marks and pending-inbox indicators (§7.1).
- Live stream: tail steps/<agent>/<NNN>/response.json event-by-event; IN_CLOSE_WRITE flips to done.
- Transcript view: readdir+sort of messages/ at a ref.
- Verbs: new root prompt, message (steer/reprompt), stop (with --stop-children), fork-from-history. All exec lernie <subcommand>.

## Must-pin items
- Separate binary (lernie-tui, crates/lernie-tui), not a lernie subcommand: frontends are pluggable readers (§3.5); keeping it out of the core binary is the severability line.
- Classification logic (lock probe, framing-tail reads) must not be reimplemented: either a small read-only lib crate shared with lernie-ui-egui, or `lernie list --json`-style read verbs. Leaning read verbs — keeps frontends dumb and the contract CLI-shaped, but adds read subcommands to a control-plane CLI. Needs a decision.
- ARCH §12 gains a milestone entry; §7 gains the TUI subsection.

## Open decisions (user)
- Framework: ratatui (ecosystem standard, pure-Rust, fits a stateless re-render loop) — recommend.
- Fate of crates/lernie-ui-egui: keep as secondary frontend or retire once the TUI ships. Recommend keep-until-TUI-parity, then decide.
- Read-verbs vs shared-lib for state classification (above).
