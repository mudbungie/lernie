`src/prompt/tool/tests/errors.rs:169` (`spawn_retries_past_transient_etxtbsy`) holds a write fd on the tool binary for 40ms and expects `ETXTBSY_RETRY_BUDGET` (200ms, src/prompt/tool/subprocess.rs) to cover it. Under parallel-agent load (load average 20-40, several tarpaulin runs at once) the holder thread's 40ms sleep plus scheduling routinely exceeds the 200ms budget and the test fails: 'retry budget covers the ~40ms hold: Spawn { ... ExecutableFileBusy }'. Observed failing on three consecutive `make check` runs on 2026-07-25 (and passing on a fourth when the box was quieter), on a tree whose only change was tests/command_surface_parity/ — i.e. unrelated to the change under test. It blocks every close gate whenever the machine is busy. Fix so the test is deterministic rather than load-sensitive: make the hold observable (release the fd on a signal the spawner has already retried at least once) rather than timed, or make the budget a test-injected parameter instead of a wall-clock constant shared with production.
