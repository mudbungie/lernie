Implement ARCHITECTURE §2.3 'The transcript writer' (spec lands via bl-a847). The executor streams the one adapter pass to two sinks: the diagnostic response.json (unchanged, §4.4) and a staging file at steps/<agent-id>/<NNN>/assistant.staging.json, appended block-by-block as each content block completes — only the in-progress block's deltas buffer in RAM. Segment authority drives staging mechanically: an Error-terminated segment truncates it; a Pause-terminated segment leaves it accumulating (the pause continuation re-sends the staging file's blocks — the writer's own sink, not a diagnostic read); the final Finish seals it — rename into the worktree as messages/NNN-assistant.json (NNN = max-present-plus-one, evaluated inside the executor's serialized commit section) and commit. A call that never settles complete (retries exhausted, non-retryable, stop) commits nothing: no transcript entry, branch tip unmoved, stale staging is debris the re-run overwrites. Also: the tool executor commits messages/NNN-tool.json (canonical tool_result — stdout as content, stderr concatenated on non-zero exit, is_error, tool_use_id) as each tool resolves (§3.3). Out of scope: re-pointing the assembler (separate ball, needs this one).
